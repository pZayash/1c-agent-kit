# COM-доступ к файловой ИБ 1С — аварийный fallback

**Статус:** аварийный режим, а не канал доступа. По умолчанию — **только чтение**
и **только после вопроса оператору**. Проектная лестница каналов и привязки —
в doc проекта (напр. `docs/ai/com-fallback-access.md`), здесь — generic-правила.

## Когда допустим

Все обычные каналы к живой ИБ недоступны (MCP мёртв, сервер/публикацию не
поднять), файловую ИБ держит чужой сеанс (тонкий клиент оператора), прерывать
его нельзя, а задача не терпит. COM-внешнее соединение встаёт к файловой ИБ
в shared-режиме рядом с клиентским сеансом — без остановки работы.

## Правила

- **Спросить оператора до подключения.** COM открывает полноценный сеанс ИБ под
  указанной учёткой: виден в списке сеансов, занимает лицензию, обходит
  ACL/аудит MCP-эндпоинтов.
- **Чтение по умолчанию.** Запись через COM опасна: нет guard'ов MCP, права —
  права учётки из строки подключения, `SetPrivilegedMode(true)` снимает и их.
  Изменение данных — только с явного разрешения оператора и с бэкапом
  изменяемого значения (напр. `ЗначениеВСтрокуВнутр` в файл до правки).
- **Prod — запрет.** COM не ходит в prod-ИБ ни при каких условиях.
- **`comcntr.dll` самому не регистрировать** (`regsvr32` требует админа и меняет
  системную регистрацию коннектора для всех). Несовпадение версий — эскалация
  оператору, регистрация только по его поручению.
- Секреты/учётки ИБ — из локального env, в артефакты и логи не печатать.

## Ограничения

- **Только Windows** + установленная платформа 1С с COM-регистрацией.
- **ProgID и `comcntr.dll` должны совпадать с версией платформы базы**
  (`V8x.Application`, `V8x.COMConnector`; x — мажор платформы). В реестре может
  быть зарегистрирована другая версия → `Connect` падает «класс не
  зарегистрирован» / 0x80040154.
- Файловая ИБ: внешнее соединение встаёт **в shared-режиме рядом с тонким
  клиентом**, но НЕ рядом с конфигуратором или сервером, держащим монопольный
  лок.
- `Выполнить`/`Вычислить` через COM недоступны (конструкции языка, не методы);
  работают `NewObject("Запрос")`, менеджеры метаданных, `ХранилищеЗначения`.
- Общий модуль вызывается только при флаге «Внешнее соединение» на модуле.

## Инструментарий

- **JScript через `cscript //nologo probe.js`** — рабочий вариант; файл в
  Unicode (UTF-16), иначе кириллица в именах методов/запросе ломается.
- **VBScript** — нет кириллицы в исходнике. **PowerShell** — плохо маршалит
  сложные типы и out-параметры (`Структура.Свойство(имя, ref)`).
- Два ProgID: `V8x.Application` (automation server, `app.Connect(...)`, далее
  `app.NewObject(...)`) и `V8x.COMConnector` (внешнее соединение,
  `connector.Connect(...)` → объект соединения).
- Результат писать в файл (`Scripting.FileSystemObject`, Unicode) — консоль
  cscript теряет кодировку.

## Если потребность повторяется

Ad-hoc cscript не делать регулярным каналом. Альтернатива — COM-MCP с
отдельной read-only учёткой ИБ (напр. `onecscripting-mcp`: профили баз,
ограниченный BSL-рантайм, пул коннектов, агентские guardrails). Установка —
решение оператора.
