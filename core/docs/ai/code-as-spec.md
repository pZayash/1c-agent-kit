# code-as-spec — требования в анкерах кода (рамка)

Единый механизм: по мере реализации change требования переносятся из prose
спек в **анкеры над носителем в коде** — код становится источником истины о
«почему так сделано». Читатель кода (агент или сторонний подрядчик без
доступа к репо документации) получает полное представление из самого кода.
Доктрина dissolve из [spec-workflow.md](spec-workflow.md) — это её механизм.

> **Граница.** Здесь — стеко-нейтральные принципы. Синтаксис анкера,
> определение метода-носителя и инструменты — в binding-доке стека
> `stacks/<s>/docs/ai/code-as-spec-<s>.md`.

## 1. Анкер-блок

Над носителем требования (функция/метод/класс/модуль — по binding стека)
ставится комментарий-блок:

```
<comment-syn> СПЕЦИФИКАЦИЯ
<comment-syn> REQUIREMENT: REQ-NNN — <краткое имя>
<comment-syn>
<comment-syn> <полный prose требования из спеки>
<comment-syn>
<comment-syn> VERIFIED-BY: <имя теста или (no-test)>
```

- `REQUIREMENT: REQ-NNN` — стабильный идентификатор; один REQUIREMENT —
  один носитель (или явный список носителей).
- `MODULE_CONTRACT` — анкер контракта модуля/сервиса (что гарантирует
  целиком), ставится над модульной сигнатурой.
- `VERIFIED-BY` — ссылка на проверку; `(no-test)` — осознанное отсутствие,
  не забвение.
- prose переносится **полностью** — анкер самодостаточен, читатель кода не
  обязан открывать спеку.

## 2. Источник истины и render-маркер

- До миграции prose живёт в `specs/<cap>/spec.md` — источник на фазе change.
- При миграции prose переносится в анкеры; в `specs/<cap>/spec.md` ставится
  маркер `<!-- code-as-spec: render -->` (после заголовка, перед Purpose):
  **источник теперь код**, spec.md — производная.
- На archive render-capability **пересобирается из анкеров** binding-
  инструментом стека (для 1С — `spec-lint render`), а не мерджится prose-
  дельтой. Render обязан отказывать при 0 анкеров — маркер не должен молча
  стирать prose-спеку (признак неверно поставленного маркера).
- Hybrid (prose + анкеры) — маркер не ставить до полного переноса.
- Первый render при отсутствии `specs/<cap>/spec.md`: сначала seed библиотеки
  из дельты (Purpose + маркер), потом render.

## 3. Миграция при apply (prose → код)

Порядок внутри change, затрагивающего код продукта:

1. Прочитать связанные `specs/<cap>/spec.md`. Маркер render уже есть → код —
   источник, миграция не нужна.
2. Для каждого prose Requirement найти носителя (правила сопоставления — в
   binding стека; fallback — tasks.md явно указывает REQ → носитель).
3. Вставить анкер-блок над носителем.
4. Поставить render-маркер в спеке capability.
5. Prose при первой миграции не удалять — render на archive пересоберёт.

## 4. Анти-дрифт

- Изменение требования по ходу apply (устно от пользователя) нельзя
  оставлять только в чате: захват в `implementation-notes.md` (цитата + дата
  + источник), затем по гейту размера — малый → дописать delta с readback;
  структурный → стоп, новый propose.
- Код без обновлённой спеки/анкера — молчаливый дрифт, расхождение для
  ревью. Проверки binding-инструмента (напр. `spec-lint check`) не зелёные →
  предупредить, не блокировать apply.

## 5. Владелец кода (OWNER)

Перед правкой метода/модуля определить владельца. Маркер `OWNER:` с областью
(метод > регион > модуль); дефолт — по правилу стека (binding). Значения:

| OWNER | Режим правки |
| --- | --- |
| `agent` | black box: рефактор, консолидация дублей, фикс смежного без спроса; отчёт — по diff |
| `human` | копилот: минимальный diff, найденные проблемы сообщать, не чинить без спроса |
| `vendor` | read-only: доработка только через разрешённые точки расширения стека |

- `tasks.md`/`design.md` могут назначать маркеры `OWNER:` — расставить по
  решению. Спор о владельце — пауза и вопрос оператору, не гадать.
- Архитектура и приёмка результата — всегда за человеком.

## 6. Связь с валидаторами

`kit_spec.py validate` проверяет структуру спек/дельт. Консистентность
анкеров с кодом (оторванные анкеры, дрифт) — забота binding-инструментов
стека; их вызовы и бюджеты — в `code-as-spec-<s>.md` и компаньонах
`spec-apply-<s>` / `spec-archive-<s>`.
