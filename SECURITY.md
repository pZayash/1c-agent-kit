# Security Policy

## Supported versions

Поддерживается только последний коммит ветки `master`. Исправления
безопасности выходят в `master`; отдельных LTS-веток/тегов нет.

| Version | Supported |
| --- | --- |
| `master` (latest) | ✅ |
| прочие ветки / теги | ❌ |

## Reporting a vulnerability

**Не открывай публичный issue с уязвимостью и не выкладывай секреты.**

- **Приватно (основной канал):** GitHub → вкладка *Security* → *Report a
  vulnerability* (GitHub Security Advisory). Виден только maintainer'ам.

В отчёте укажи:

- затронутый файл/скрипт и версию (коммит);
- шаги воспроизведения;
- возможное влияние;
- предлагаемый фикс (если есть).

## Scope

Только уязвимости **этого репозитория** (kit). Внутренние системы
потребителей, их базы 1С и развёртывания — вне скоупа; о них сообщай
владельцу той системы.

## Response / disclosure

- Подтверждение получения — в течение ~7 дней.
- Фикс — в `master` после подтверждения.
- Публичное раскрытие — после выхода фикса, координированно и по
  договорённости с репортёром.

## Guidelines

- Репозиторий **публичный**: не публикуй в issues/PR секреты, токены,
  пароли, строки подключения к 1С, внутренние IP/имена хостов.
- Если секрет случайно попал в коммит — отзови его (rotate) и напиши
  maintainer'у приватно. Удаления коммита недостаточно: история видна.
