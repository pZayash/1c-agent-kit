# Правила написания запросов 1С для ИИ-агентов

## Когда использовать

При написании запросов 1С, запросов динамических списков и запросов СКД.

## Формат ответа

Если задача просит текст запроса, возвращай именно сырой текст языка запросов 1С: первый значимый оператор должен быть `ВЫБРАТЬ`. Не оборачивай запрос в строковый литерал BSL, не добавляй `Запрос = Новый Запрос`, `Запрос.Текст =`, `УстановитьПараметр`, `Выгрузить()` или другой модульный код.

Когда нужен запрос для `syntaxcheck` или другой проверки, не добавляй внешние кавычки и обязательные префиксы `|` в начале строк. Markdown-блок допустим, но внутри него должен быть только текст запроса. Если нужно подготовить пустой набор данных, всё равно сформируй запрос, например через `ВЫБРАТЬ ПЕРВЫЕ 0 ...`, а не список полей или BSL-создание `ТаблицаЗначений`.

## Правила

### Использование временных таблиц

- Всегда используй временные таблицы вместо вложенных запросов. Оптимизатор баз данных гораздо лучше и более предсказуемо справляется с временными таблицами.
- Переиспользуй данные временных таблиц в запросе где это возможно, не создавай дубли.
- Используй временные таблицы для выборки данных из виртуальных таблиц, не соединяй реальные таблицы с виртуальными непосредственно.
- Используй временные таблицы, если надо собрать данные из нескольких источников. Сначала собери во временную таблицу, потом используй ее далее в запросе

### Избегание ошибки неоднозначности полей

В 1С при работе с запросами, содержащими JOIN с табличными частями документов, может возникать ошибка **"Неоднозначное поле"**. Это происходит когда псевдоним таблицы в запросе совпадает с именем реквизита объекта.

**Пример ошибки:**

```text
Ошибка при вызове метода контекста (Выполнить): {(14, 4)}: Неоднозначное поле "РасшифровкаПлатежа.СуммаПлатежа"
```

### Причина

1С не может определить, к чему относится ссылка на поле:

- К псевдониму таблицы запроса?
- К реквизиту объекта документа?

### Решение

**Всегда используй уникальные псевдонимы для таблиц в запросах!**

#### Правильный подход

```1c
// НЕПРАВИЛЬНО - псевдоним совпадает с именем табличной части документа
ИЗ
|   Документ.ПоступлениеНаСчет КАК ТаблицаДокументов
|       ВНУТРЕННЕЕ СОЕДИНЕНИЕ Документ.ПоступлениеНаСчет.РасшифровкаПлатежа КАК РасшифровкаПлатежа
|   ПО ТаблицаДокументов.Ссылка = РасшифровкаПлатежа.Ссылка

// ПРАВИЛЬНО - уникальный псевдоним
ИЗ
|   Документ.ПоступлениеНаСчет КАК ТаблицаДокументов
|       ВНУТРЕННЕЕ СОЕДИНЕНИЕ Документ.ПоступлениеНаСчет.РасшифровкаПлатежа КАК РасшифровкаПлатежаТС
|   ПО ТаблицаДокументов.Ссылка = РасшифровкаПлатежаТС.Ссылка
```

#### Рекомендации по псевдонимом

- Для табличных частей добавляй суффиксы: `ТС`, `ТЧ`, `TabularSection`
- Используй описательные псевдонимы: `РасшифровкаТС`, `ТоварыТЧ`
- Избегай совпадения с именами реквизитов документа

#### Полный пример исправленного запроса

```1c
запрос = Новый Запрос;
запрос.Текст =
"ВЫБРАТЬ РАЗРЕШЕННЫЕ
|   ТаблицаДокументов.Ссылка КАК Ссылка,
|   ТаблицаДокументов.Номер КАК Номер,
|   ТаблицаДокументов.Дата КАК Дата,
|   РасшифровкаПлатежаТС.НомерСтроки КАК НомерСтроки,
|   РасшифровкаПлатежаТС.СуммаПлатежа КАК СуммаПлатежа,
|   РасшифровкаПлатежаТС.СуммаРасчетов КАК СуммаРасчетов
|ИЗ
|   Документ.ПоступлениеНаСчет КАК ТаблицаДокументов
|       ВНУТРЕННЕЕ СОЕДИНЕНИЕ Документ.ПоступлениеНаСчет.РасшифровкаПлатежа КАК РасшифровкаПлатежаТС
|       ПО ТаблицаДокументов.Ссылка = РасшифровкаПлатежаТС.Ссылка
|ГДЕ
|   ТаблицаДокументов.Проведен
|   И РасшифровкаПлатежаТС.СуммаПлатежа <> РасшифровкаПлатежаТС.СуммаРасчетов
|
|УПОРЯДОЧИТЬ ПО
|   ТаблицаДокументов.Дата,
|   ТаблицаДокументов.Ссылка,
|   РасшифровкаПлатежаТС.НомерСтроки";
```

### Join vs Subquery

 ```1c
// ✅ PREFERRED: Join (usually faster)
"ВЫБРАТЬ
|    Заказы.Ссылка КАК Заказ,
|    Контрагенты.ИНН КАК ИНН
|ИЗ
|    Документ.ЗаказКлиента КАК Заказы
|        ЛЕВОЕ СОЕДИНЕНИЕ Справочник.Контрагенты КАК Контрагенты
|        ПО Заказы.Контрагент = Контрагенты.Ссылка"

// ⚠️ AVOID: Subquery in SELECT (N+1 problem)
"ВЫБРАТЬ
|    Заказы.Ссылка КАК Заказ,
|    (ВЫБРАТЬ К.ИНН ИЗ Справочник.Контрагенты КАК К 
|     ГДЕ К.Ссылка = Заказы.Контрагент) КАК ИНН
|ИЗ
|    Документ.ЗаказКлиента КАК Заказы"
```

### Avoid Aggregation in Subqueries

 ```1c
// ❌ SLOW: Subquery with aggregation
"ВЫБРАТЬ
|    Номенклатура.Ссылка,
|    (ВЫБРАТЬ СУММА(Остатки.Количество) ...) КАК Остаток
|ИЗ
|    Справочник.Номенклатура КАК Номенклатура"

// ✅ FAST: Join with pre-aggregated data
"ВЫБРАТЬ
|    Номенклатура.Ссылка КАК Номенклатура,
|    ЕСТЬNULL(Остатки.КоличествоОстаток, 0) КАК Остаток
|ИЗ
|    Справочник.Номенклатура КАК Номенклатура
|        ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыНаСкладах.Остатки КАК Остатки
|        ПО Номенклатура.Ссылка = Остатки.Номенклатура"
```

### Virtual Table Parameters

Use virtual table parameters instead of WHERE for better performance:

 ```1c
// ✅ CORRECT: Uses virtual table parameters (fast)
"ВЫБРАТЬ
|    Остатки.Номенклатура КАК Номенклатура,
|    Остатки.КоличествоОстаток КАК Остаток
|ИЗ
|    РегистрНакопления.ТоварыНаСкладах.Остатки(
|        &Дата,
|        Номенклатура В (&СписокНоменклатуры)) КАК Остатки"

// ❌ WRONG: Virtual table then filter (slow)
"ВЫБРАТЬ
|    Остатки.Номенклатура КАК Номенклатура,
|    Остатки.КоличествоОстаток КАК Остаток
|ИЗ
|    РегистрНакопления.ТоварыНаСкладах.Остатки(&Дата) КАК Остатки
|ГДЕ
|    Остатки.Номенклатура В (&СписокНоменклатуры)"
```

### DCS (Data Composition System) Optimization

1. **Use parameters in query text:**

   ```1c
   // Pass parameters to virtual table
   РегистрНакопления.Остатки.Остатки(&Период, Склад = &Склад)
   ```

2. **Limit data at source:**
   ``1c
   // Add conditions in DataSet query, not in DCS settings
   ГДЕ Период >= &НачалоПериода
   ```

3. **Use ЕСТЬNULL for outer joins:**

   ```1c
   ЕСТЬNULL(Остатки.Количество, 0) КАК Количество
   ```

### Composite Type Dereferencing (ITS Standard)

Avoid dereferencing composite type reference fields directly — the system creates queries for **ALL** possible types.

```1c
// ❌ SLOW: Dereferences ALL registrar types (can be hundreds)
"ВЫБРАТЬ
|    ТоварыНаСкладах.Регистратор.Дата КАК ДатаДокумента
|ИЗ
|    РегистрНакопления.ТоварыНаСкладах КАК ТоварыНаСкладах"

// ✅ FAST: Use ВЫРАЗИТЬ to specify exact type
"ВЫБРАТЬ
|    ВЫРАЗИТЬ(ТоварыНаСкладах.Регистратор КАК Документ.ПоступлениеТоваровУслуг).Дата КАК ДатаДокумента
|ИЗ
|    РегистрНакопления.ТоварыНаСкладах КАК ТоварыНаСкладах"

// ✅ For multiple known types, use ВЫБОР/КОГДА
"ВЫБРАТЬ
|    ВЫБОР
|        КОГДА ТоварыНаСкладах.Регистратор ССЫЛКА Документ.ПоступлениеТоваровУслуг
|            ТОГДА ВЫРАЗИТЬ(ТоварыНаСкладах.Регистратор КАК Документ.ПоступлениеТоваровУслуг).Дата
|        КОГДА ТоварыНаСкладах.Регистратор ССЫЛКА Документ.РеализацияТоваровУслуг
|            ТОГДА ВЫРАЗИТЬ(ТоварыНаСкладах.Регистратор КАК Документ.РеализацияТоваровУслуг).Дата
|    КОНЕЦ КАК ДатаДокумента
|ИЗ
|    РегистрНакопления.ТоварыНаСкладах КАК ТоварыНаСкладах"
```

### Use ПРЕДСТАВЛЕНИЕ for Display (ITS Standard)

When you only need text representation, use `ПРЕДСТАВЛЕНИЕ()` to avoid extra joins:

 ```1c
// ❌ Creates additional subquery for Справочник.Склады
"ВЫБРАТЬ
|    ТоварыНаСкладах.Склад.Наименование
|ИЗ
|    РегистрНакопления.ТоварыНаСкладах КАК ТоварыНаСкладах"

// ✅ Optimal: No extra join
"ВЫБРАТЬ
|    ПРЕДСТАВЛЕНИЕ(ТоварыНаСкладах.Склад) КАК СкладПредставление
|ИЗ
|    РегистрНакопления.ТоварыНаСкладах КАК ТоварыНаСкладах"
```

### Avoid Joins with Subqueries (ITS Standard)

Never use subqueries in JOIN — use temporary tables instead:

```1c
// ❌ WRONG: Join with subquery
"ВЫБРАТЬ ...
|ИЗ
|    Документ.Заказ КАК Заказы
|        ЛЕВОЕ СОЕДИНЕНИЕ (
|            ВЫБРАТЬ Товары.Заказ, СУММА(Товары.Сумма) КАК Сумма
|            ИЗ Документ.Заказ.Товары КАК Товары
|            СГРУППИРОВАТЬ ПО Товары.Заказ
|        ) КАК ИтогиТоваров
|        ПО Заказы.Ссылка = ИтогиТоваров.Заказ"

// ✅ CORRECT: Use temporary table
"ВЫБРАТЬ
|    Товары.Ссылка КАК Заказ,
|    СУММА(Товары.Сумма) КАК Сумма
|ПОМЕСТИТЬ ИтогиТоваров
|ИЗ
|    Документ.Заказ.Товары КАК Товары
|СГРУППИРОВАТЬ ПО
|    Товары.Ссылка
|ИНДЕКСИРОВАТЬ ПО
|    Заказ
|;
|ВЫБРАТЬ ...
|ИЗ
|    Документ.Заказ КАК Заказы
|        ЛЕВОЕ СОЕДИНЕНИЕ ИтогиТоваров КАК ИтогиТоваров
|        ПО Заказы.Ссылка = ИтогиТоваров.Заказ"
```

### Avoid Joins with Virtual Tables (ITS Standard)

Extract virtual table results to temporary table before joining:

 ```1c
// ⚠️ May be slow: Direct join with virtual table
"ВЫБРАТЬ ...
|ИЗ
|    Справочник.Номенклатура КАК Номенклатура
|        ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыНаСкладах.Остатки(&Дата,) КАК Остатки
|        ПО Номенклатура.Ссылка = Остатки.Номенклатура"

// ✅ BETTER: First extract to temporary table
"ВЫБРАТЬ
|    Остатки.Номенклатура КАК Номенклатура,
|    Остатки.КоличествоОстаток КАК Остаток
|ПОМЕСТИТЬ ВТОстатки
|ИЗ
|    РегистрНакопления.ТоварыНаСкладах.Остатки(&Дата,) КАК Остатки
|ИНДЕКСИРОВАТЬ ПО
|    Номенклатура
|;
|ВЫБРАТЬ ...
|ИЗ
|    Справочник.Номенклатура КАК Номенклатура
|        ЛЕВОЕ СОЕДИНЕНИЕ ВТОстатки КАК Остатки
|        ПО Номенклатура.Ссылка = Остатки.Номенклатура"
```

## Avoid OR in WHERE — Use ОБЪЕДИНИТЬ ВСЕ (ITS Standard)

`OR` in `WHERE` prevents index usage. Split into UNION queries:

 ```1c
// ❌ SLOW: OR prevents index usage
"ВЫБРАТЬ
|    Товары.Ссылка
|ИЗ
|    Справочник.Номенклатура КАК Товары
|ГДЕ
|    Товары.Артикул = &Артикул
|    ИЛИ Товары.Код = &Код"

// ✅ FAST: Two indexed queries with UNION
"ВЫБРАТЬ
|    Товары.Ссылка
|ИЗ
|    Справочник.Номенклатура КАК Товары
|ГДЕ
|    Товары.Артикул = &Артикул
|
|ОБЪЕДИНИТЬ ВСЕ
|
|ВЫБРАТЬ
|    Товары.Ссылка
|ИЗ
|    Справочник.Номенклатура КАК Товары
|ГДЕ
|    Товары.Код = &Код"
```

## ОБЪЕДИНИТЬ vs ОБЪЕДИНИТЬ ВСЕ (ITS Standard)

Prefer `ОБЪЕДИНИТЬ ВСЕ` when no duplicate rows expected:

 ```1c
// ⚠️ SLOWER: ОБЪЕДИНИТЬ performs additional grouping
"ВЫБРАТЬ ... ИЗ Документ.Приход
|ОБЪЕДИНИТЬ
|ВЫБРАТЬ ... ИЗ Документ.Расход"

// ✅ FASTER: ОБЪЕДИНИТЬ ВСЕ skips grouping
"ВЫБРАТЬ ... ИЗ Документ.Приход
|ОБЪЕДИНИТЬ ВСЕ
|ВЫБРАТЬ ... ИЗ Документ.Расход"
```

### Index Alignment (ITS Standard)

Ensure query conditions match available indexes:

1. Index must contain **all fields** from the condition
2. Fields must be at the **beginning** of the index
3. Fields must be **consecutive** (no gaps)
4. Add `ИНДЕКСИРОВАТЬ ПО` for temporary tables used in joins

 ```1c
// Given index: (Организация, Контрагент, Дата)

// ✅ Index will be used — fields are at the beginning
"ГДЕ Организация = &Орг И Контрагент = &Контр"

// ❌ Index NOT used — skipped first field
"ГДЕ Контрагент = &Контр И Дата = &Дата"

// ⚠️ Partial use — gap in fields
"ГДЕ Организация = &Орг И Дата = &Дата"
```

**Reference**: [ITS Query Optimization Standards](https://its.1c.ru/db/v8std/browse/13/-1/26/28)

**Remember**: Перед написанием запроса проверь через `search_metadata` все используемые объекты метаданных, табличные части, допустимые источники данных, поля, измерения, ресурсы и значения перечислений. Для регистра отдельно уточняй, существует ли нужная виртуальная таблица (`Остатки`, `Обороты`, `ОстаткиИОбороты`) или нужно читать основную таблицу регистра. Для каждого поля из `ВЫБРАТЬ`, `ГДЕ`, `ПО`, `СГРУППИРОВАТЬ ПО`, `ИМЕЮЩИЕ` и `ИНДЕКСИРОВАТЬ ПО` убедись, что оно реально есть в выбранном источнике.

**Remember**: Не выводи имена регистров, полей и значений `ЗНАЧЕНИЕ(...)` из смысла задачи, названий временных таблиц или похожих объектов. Для уже переданных ВТ используй имя ВТ из задачи буквально и обращайся только к явно заданным колонкам или колонкам, сформированным в предыдущих пакетах запроса. После написания запроса проверь одинаковость всех псевдонимов и имен ВТ посимвольно.

**Remember**: Используй инструмент `syntaxcheck` для проверки текстов запросов.

### Семантическая самопроверка после syntaxcheck

- В ветках `ОБЪЕДИНИТЬ ВСЕ` сохраняй одинаковый порядок, смысл и совместимые типы колонок; во второй и следующих ветках пиши выражения так, чтобы их можно было сверить с первой веткой без догадок.
- Не соединяй подготовленные строки и текущие движения по неполному набору измерений: пропущенное измерение даст дубли или смешает разные аналитики, даже если запрос пройдет проверку синтаксиса.
- Не оставляй выборку из регистра без фильтра по `&Регистратор`, если задача относится к движениям конкретного документа или записи.
- Не дублируй одно и то же поле движения под разными алиасами как «изменение» или «перед записью», если нет явного расчета или понятной схемы объединения источников.
- Перед ответом проверь, что текст запроса не содержит незавершенных операторов после `;`, заготовочных хвостов и служебного текста вне запроса.
