# Code Analysis Orchestrator для 1С

## Когда использовать

- Найти источник данных в реквизите формы/объекта
- Построить цепочку вызовов через несколько модулей
- Понять архитектуру подсистемы
- Разобрать end-to-end flow бизнес-процесса

**НЕ нужен** для простых задач (1-2 поиска, известный модуль, чтение одного файла).

## Кодовая база

Конфигурация выгружена в `conf/` в hierarchical XML+BSL формате:

```
conf/
  CommonModules/Имя/Ext/Module.bsl
  Documents/Имя/Ext/ObjectModule.bsl
  Documents/Имя/Forms/ИмяФормы/Ext/Form/Module.bsl
  Catalogs/Имя/Ext/ObjectModule.bsl
  AccumulationRegisters/Имя/Ext/RecordSetModule.bsl
```

## Стратегия оркестрации

### Шаг 0. Предварительная разведка

Перед запуском субагентов **оркестратор сам** собирает контекст:

1. **`search_metadata`** — если в запросе упоминается объект, получи его структуру
2. **`docsearch`** — если нужно уточнить API платформы
3. **Быстрый grep** через Grep tool — найти ключевые модули по имени

Результаты разведки **передай в промпты субагентам**.

### Шаг 1. Декомпозиция задачи

| Тип подзадачи | Субагент | Когда назначать |
|---|---|---|
| Поиск вхождений ключевого слова | `1c-code-search` | Всегда при трассировке |
| Трассировка цепочки вызовов A->B->C | `1c-call-trace` | "как это работает" |
| Анализ потока данных | `1c-data-flow` | "откуда берётся" |
| Структура конфигурации, метаданные | `1c-config-explorer` | Архитектурные вопросы |

**Опционально**: сначала запусти только search; по результату сформулируй узкие подзадачи для trace и data-flow.

### Шаг 2. Параллельный запуск субагентов

Запускай 2-4 субагента **одновременно** через Agent tool:

```
Agent(prompt="[задание для SearchAgent]", description="1c-code-search", subagent_type="Explore")
Agent(prompt="[задание для TraceAgent]", description="1c-call-trace", subagent_type="Explore")
```

**Критично**: каждый субагент должен получить полный самодостаточный промпт с:

- Конкретной задачей (что искать)
- Инструкцией по инструментам (rlm-tools-bsl или Grep/Read)
- Контекстом из Шага 0
- Форматом ответа
- Без confirmation bias: не писать ожидаемый вывод («найди баг в X»).
  Задание — исследовать / сравнить. В ответе — uncertainty и альтернативы.

### Шаг 3. Синтез результатов

1. Объедини находки, убери дубли
2. Построй mermaid flowchart
3. Выдай структурированный ответ (см. формат ниже)

## Промпт субагента

Каждый субагент получает:

```
Ты -- специализированный агент для анализа кода 1С.

Задача: [конкретная задача]

Контекст из метаданных (от оркестратора):
  [структура объектов, найденные модули]

Кодовая база: conf/ (hierarchical XML+BSL)
  CommonModules/Имя/Ext/Module.bsl
  Documents/Имя/Ext/ObjectModule.bsl

Инструменты: используй Grep и Read для поиска и чтения файлов.
  - Grep: pattern="ИмяПроцедуры", path="conf/", glob="*.bsl"
  - Read: file_path для чтения найденных файлов
  - grep-ast (bash): python -m grep_ast "паттерн" "файл.bsl" -- контекст функции

Альтернатива для массового поиска -- MCP rlm-tools-bsl:
  - rlm_projects(action='add', name='proj', path='<host-путь репо>', password='…')  -- разово
  - rlm_index(action='build', project='proj', password='…')  -- разово, обязателен для conf/
  - rlm_start(project='proj', query='описание')
  - rlm_execute(python_code) -- всегда print()
  - rlm_end()

  57 BSL-хелперов (модули, граф вызовов, ссылки метаданных, формы/СКД).
  Точные имена/сигнатуры -- rlm_help('<helper>') или docs/HELPERS.md форка, не угадывать.
  Канон: docs/ai/rlm-tools-bsl.md

Что вернуть:
[конкретный список -- процедуры, строки кода, модули, схема]
```

### Формат ответа субагента

Обязательные разделы:

- `## Ключевые процедуры` -- список с файлами и строками
- `## Цепочка вызовов` и/или `## Поток данных`
- `## Файлы` -- пути к модулям
- `## Uncertainty` -- пробелы в данных, альтернативы, если вывод неоднозначен

## Формат итогового ответа оркестратора

```markdown
## Краткий ответ
[1-2 предложения]

## Схема потока
[mermaid flowchart]

## Детальный разбор
### Ключевые процедуры
[Модуль.Процедура -- что делает, строка ~N]

### Цепочка вызовов
[A -> B -> C -> D с пояснениями]

### Источник данных
[Откуда -> куда -> итог]

## Найденный код
[Ключевые фрагменты BSL]
```

## Паттерны типичных запросов

### "Откуда в реквизит X попадает значение?"

Параллельно:

1. **Search**: найти все присвоения реквизита X
2. **Trace**: трассировать вызов процедуры вверх по стеку
3. **DataFlow**: откуда берётся правая часть присвоения

### "Как работает [механизм]?"

Параллельно:

1. **Search**: найти ключевые процедуры по имени
2. **Trace**: построить call chain от точки входа
3. **Config**: найти регистры/макеты, участвующие в механизме

### "Архитектура подсистемы"

Параллельно:

1. **Config**: все модули подсистемы + экспортные процедуры
2. **Search**: точки входа (публичный API)
3. **Trace**: ключевые сценарии
