# Правила создания тестов 1С для ИИ-агентов

Подробнее: [docs/ai/testing.md](../../../docs/ai/testing.md).

## Размещение тестов

Тесты разнесены по модулям подсистемы `яя_тесты` (отдельного общего модуля `яя_тесты` в конфигурации нет):

| Модуль | Когда использовать |
| --- | --- |
| `яя_тестыСервер` | Метаданные, права, подписки, пользователи ИБ, MCP, запись пустых объектов |
| `яя_тестыПечать` | Печать `яя_Печать_*`, ДОиО, роли на печать |
| `яя_тестыКлиент` | Клиент (формы, UI) |
| `яя_тестыДанных` | SQL-смоук, целостность ИБ, поведенческие тесты с записью |

**Не в `яя_тесты*`:** утилиты миграции/патчей → модуль `яя_`.

### `яя_тестыДанных`: подтипы

| Подтип | `СписокТестов()` | Пример |
| --- | --- | --- |
| Смоук | Да | `Тест_РасходнаяНакладная_НетПустыхТНВЭДПриЭкспорте` |
| Поведенческий | Да | `Тест_РасходнаяНакладная_ЗаполненныйКодТНВЭДНеЗатирается` |
| Точечный валидатор | **Нет** | `Тест_РасходнаяНакладная_ТНВЭДПриЭкспорте(пДокумент)` из менеджера |

В выбранном модуле:

- область `#Область Тесты ... #КонецОбласти`;
- смоук/поведенческий — экспорт без обязательных параметров + строка в **`СписокТестов()`**;
- точечный — экспорт с параметром ссылки, **без** строки в `СписокТестов()`.

## Именование тестов

- Процедуры тестов начинаются с префикса `Тест_`
- Имя теста должно отражать что тестируется: `Тест_<Объект>_<ЧтоПроверяется>`
- Примеры: `Тест_РольБазовыеПрава_ПрисоединенныеФайлы`, `Тест_Пользователи_НетПраваИнтерактивногоОткрытияВнешнихОтчетовИОбработок`

## Покрытие сценариев

Каждый Scenario спеки с THEN вида «значение **НЕ** изменяется / не падает / не
заполняется» требует **отдельного негативного теста**. Позитивный тест
(«заполнилось») не покрывает сохранение состояния. Пропуск негативного теста —
типовой источник скрытых багов (значение молча перезаписывается или затирается).

## Структура процедуры теста

- Процедура всегда `Экспорт`
- Комментарий перед процедурой описывает что проверяет тест
- Метка автора и даты: `// +org <Автор> ГГММДД`

### Паттерн сбора ошибок

```1c
ошибки = Новый Массив;
// ... проверки с добавлением ошибок в массив ...
Если ошибки.Количество() > 0 Тогда
ВызватьИсключение СтрСоединить(ошибки, Символы.ПС);
КонецЕсли;
```

### Формат сообщений об ошибках

- Использовать `СтрШаблон()` для формирования понятных сообщений
- Указывать конкретный объект и что именно не так
- Если ошибка связана со ссылочным объектом типа СправочникСсылка, ДокументСсылка и т.п., выводить в сообщение об ошибке навигационную ссылку, полученную с помощью метода `ПолучитьНавигационнуюСсылку`

Пример:

```1c
текстОшибки = СтрШаблон("У роли '%1' отсутствует право '%2' для справочника '%3'",
        рольМетаданные.Имя,
        имяПрава,
        метаСправочника.ПолноеИмя()
    );
ошибки.Добавить(текстОшибки);
```

### Полный шаблон процедуры теста

```1c
// Тест проверяет <что проверяет>.
// <Дополнительное описание при необходимости>.
//
// +org author 260112 
Процедура Тест_ИмяТеста() Экспорт
    
    // Подготовка данных
    данныеДляПроверки = яя_конст.МетодПолучения();
    
    ошибки = Новый Массив;
    
    // Проверки
    Для Каждого элемент Из данныеДляПроверки Цикл
        
        Если Не УсловиеВыполнено(элемент) Тогда
            текстОшибки = СтрШаблон( "Описание ошибки для '%1'",
                                     элемент // %1
                                     ...    );
            ошибки.Добавить(текстОшибки);
            
        КонецЕсли;
        
    КонецЦикла;
    
    // Результат
    Если ошибки.Количество() > 0 Тогда
        ВызватьИсключение СтрСоединить(ошибки, Символы.ПС);
        
    КонецЕсли;
    
КонецПроцедуры

```

## Запуск

`МодульТестов.ОтчетОТестировании()` или `яя_клиентСервер.ОтчетОТестировании("яя_тестыСервер")` — транзакция с откатом.
