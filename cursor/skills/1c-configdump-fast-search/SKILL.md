# Быстрый и устойчивый поиск по конфиг-дампу 1С в `conf/` (anti-timeout)

## Зачем это нужно

Репозиторий большой, папка `conf/` тяжёлая. «Широкие» поиски и листинги по всему репозиторию или по всему `conf/` часто дают таймауты и много шума.

Цель: **сначала** выбрать правильный инструмент по иерархии проекта, **затем** сузить область и найти 1–5 релевантных файлов, **потом** читать их.

## Порядок инструментов (как в проектной документации)

Согласовано с [`AGENTS.md`](../../../AGENTS.md) / [`CLAUDE.md`](../../../CLAUDE.md) — этот скилл — **запасной путь**, когда штатные инструменты недоступны или нужен ручной узкий поиск.

1. **Справка платформы** — `docsearch` (методы/свойства 1С), не обход `conf/` «вслепую».
2. **Метаданные** — `search_metadata` (существование объектов, структура).
3. **Массовый поиск/чтение в `conf/`** — песочница [`rlm-tools-bsl`](../../../docs/ai/rlm-tools-bsl.md): `rlm_start(project='proj')` → `rlm_execute` с BSL-хелперами в сессии (данные на сервере, в контекст — короткие `print()`-выводы; имена хелперов — `rlm_help`).
4. **Уже есть путь к файлу(ам), нужен контекст процедуры/запроса** — [`grep-ast`](../../../docs/ai/grep-ast.md) по конкретным `.bsl` (AST, не «голые строки»).
5. **Агент Cursor** — встроенные **семантический поиск** и **grep (ripgrep)** с обязательным сужением `path` и `glob` (например только `*.bsl`). Это **не** то же самое, что запуск `grep -r` по всему `conf/` в терминале.
6. **Этот скилл** — тактика сужения области, якорей и путей, если нужно искать вручную или инструменты выше недоступны.

**Не путать:** запрет в проекте относится к **консольному** обходу большой `conf/` (`grep`/`find` без границ). Узкий `path` + маска файлов — допустимы; предпочтительнее встроенные инструменты IDE с лимитами.

## Правила поиска (по умолчанию)

- **Сужать область**: начинать с конкретных каталогов (`conf/CommonModules/`, `conf/DataProcessors/`, `conf/Documents/` и т.д.).
- **Сужать тип файлов**: для кода — в основном `*.bsl`; `*.xml` — для метаданных и форм, когда это нужно.
- **Сначала путь к файлу, потом чтение**: не пытаться «сразу найти всё» в одном запросе.
- **Не листить `conf/` целиком**: если нужен список — фильтр по имени/маске и короткий вывод.
- **Консоль в проекте**: без `cd`/`git -C` в начале команд; относительные пути от корня репозитория; префикс `rtk` для оптимизации вывода — см. [`AGENTS.md`](../../../AGENTS.md).

## Тактики против таймаутов

- **Таймаут или слишком много совпадений**:
  - сузить `path` до 1–2 подкаталогов;
  - ограничить `glob` до `*.bsl`;
  - искать по редким якорям (`ПередДобавлениемКомандПечати`, `СведенияОВнешнейОбработке`), затем открывать найденные файлы.
- **Поиск объекта по имени (например `яя_Печать_*`)**:
  - не рекурсировать весь `conf/`;
  - сразу нужный вид метаданных, например обработки: `conf/DataProcessors/яя_Печать_*`, общие модули: `conf/CommonModules/яя_*`.

## Шаблоны путей (быстрые попадания)

- **Обработки**: `conf/DataProcessors/<Имя>/Ext/ManagerModule.bsl`, модуль объекта: `.../Ext/ObjectModule.bsl`
- **Общие модули**: `conf/CommonModules/<Имя>/Ext/Module.bsl`
- **Формы**: `.../Forms/<ИмяФормы>/Ext/Form/Module.bsl`

## Семантика требований: «модуль формы» vs «модуль объекта»

Если в задаче: «в модуле обработки должна быть экспортная `СведенияОВнешнейОбработке()`» — для внешней обработки это обычно **модуль объекта**, чтобы срабатывал вызов:

```bsl
ВнешнийОбъект = Обработки.ИмяОбработки.Создать();
Сведения = ВнешнийОбъект.СведенияОВнешнейОбработке();
```

то есть реализация в `Ext/ObjectModule.bsl`, а не только в модуле формы.
