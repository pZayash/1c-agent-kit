# Правила документирования методов в 1С

## Общие положения

Терминм `Метод` обобщает и процеды и функции вместе

Документирующие комментарии обязательны для всех экспортных методов. Для внутренних методов документирование рекомендуется.

Комментарии пишутся на русском языке, начинаются с `//` и размещаются непосредственно перед объявлением метода.

**Не вставлять новый метод между документирующим комментом и его функцией.** При
добавлении метода рядом с существующим — размещать его **до** блока коммента
соседа или **после** тела соседа, чтобы doc-коммент не оторвался от своего метода.
Признак ошибки: коммент `// Возвращаемое значение: Строка…` стоит над функцией,
возвращающей `СправочникСсылка` — значит вставка разорвала пару коммент↔метод.

Синтаксическим отступом в комментариях является два пробела `  `

Длина строки комментария не должна превышать 120 символов

При переносе строки комментария на следующу строку, добавлять два синтаксических отступа, например для длинных описаний параметров

В любом месте документирующего комментария можно добавить переход к другим объектам конфигурации, процедурам и функциям (в частности, для перехода к функциям-конструкторам структур).

```1c
// Описание универсальной процедуры.
// 
// См. УправлениеДоступом.ЗаполнитьНаборыЗначенийДоступа
//
// Параметры:
//   Параметр1 – Произвольный – описание параметра см. Справочник.Контрагенты.
//
Процедура УниверсальнаяПроцедура(Параметр1)
...
```

Устаревшие методы помечаются словом "Устарела" (англ. "Deprecated") в первой строке

В методах с директивами компиляции `&...` сначала надо размещать комментарий, а затем - директиву компиляции.

```1c
// Jбработчик события формы ПриСозданииНаСервере.
// Также выполняет следующие действия:
// ...
//
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
```

## Разделы комментария

### Секция `Описание` (англ. "Description")

- Содержит краткое описание назначения метода, достаточное для понимания сценариев ее использования без просмотра ее исходного кода
- Может содержать краткое описание принципов работы и перекрестные ссылки на связанные процедуры и функции.
- Начинается с заглавной буквы, заканчивается точкой
- Для функций описывает что возвращает, для процедур - что делает

- Может быть единственной секцией для процедур без параметров
- Описание не должно совпадать с именем метода
- Не начинать описание с избыточных слов «Процедура...», «Функция...»
- Для процедур и функций секция должна начинаться с глагола.
  - Для функций «Возвращает…», «Проверяет…», «Сравнивает…», «Вычисляет…» и т.п.

### Секция `Параметры` (англ. Parameters)

- Обязательно для методов c параметрами
- Если параметров нет, секция пропускается.
- Предваряется строкой "Параметры:"
- Затем с новой строки размещаются описания всех параметров, **Формат**: `ИмяПараметра - Тип - Описание`
  - Тип параметра указывается в соответствии с типами 1С (Строка, Структура, Произвольный, СправочникСсылка.Сотрудники и т.п.)
  - Описание рекомендуется заполнять только когда имени параметра недостаточно для понимания его назначения, или надо дать информацию о типе параметра или пример с ожидаемым значением параметра

```1c
// Параметры:
//   ИмяПараметра1 - Строка - Имя сотрудника
//   ИмяПараметра2 - СправочникСсылка.Сотрудники
```

#### Для параметров типа `Массив` следует указывать тип элементов с помощью ключевого слова "из" (англ. "of")

```1c
// СведенияОбОбновлении  - Массив из см. ОбновлениеИнформационнойБазы.ПараметрыОбновления
// Сотрудники  - Массив из СправочникСсылка.Сотрудники 
```

Допускается не указывать тип элементов массивов только в методах, которые работают с массивами универсальным образом.

#### Для параметров типа `Структура`, `ТаблицаЗначений` и `ДеревоЗначений`

**Описание ссылкой на функцию**, выходным значением которой является этот параметр. Например, ссылку на функцию-конструктор. Все допустимые параметры должны быть определены явно в функции-конструкторе

```1c
// Заполняет цены в строке табличной части
// Параметры:
//   ТекущаяСтрока – СтрокаТабличнойЧасти
//   ПараметрыЗаполненияЦен – см. ЦенообразованиеСервер.ПараметрыЗаполненияЦен
//
Процедура ЗаполнитьЦеныВСтрокеТЧ(ТекущаяСтрока, ПараметрыЗаполненияЦен)
...
```

**Описание возвращаемых таблиц значений:**

```1c
// Возвращаемое значение:
//   ТаблицаЗначений:
//     * Серия - СправочникСсылка.СерииНоменклатуры - если серия указана и она может
//               использоваться с новым значением номенклатуры на указанном складе,
//               то возвращается переданное значение; если нет - пустая ссылка.
//     * СтатусУказанияСерий - Число - если серии указываются в ТЧ "Товары", то
//               возвращается рассчитанный статус; если для переданной
//               номенклатуры/склада серии не используется - возвращается 0,
//               иначе возвращается переданный статус.
```

**Описание структур и вложенных структуры:**

```1c
// Параметры:
//   СведенияОбОбновлении - Структура:
//     * КодАдресногоОбъекта - Структура:
//        ** КодРегиона - Число - код региона (длина - 2).
//        ** КодНаселенногоПункта - Число - код населенного пункта (длина - 3).
//        ** КодУлицы - Число - код улицы (длина - 4).
//     * Наименование - Строка
//     * ОбновлениеДоступно - Булево
```

#### Для параметра типа `СтрокаТаблицыЗначений` и `СтрокаДереваЗначений` возможно задать состав свойств, соответствующий колонкам его таблицы-владельца (дерева-владельца)

```1c
// Параметры:
//   СведенияОРегионе – СтрокаТаблицыЗначений: см. РегистрыСведений.АдресныеОбъекты.КлассификаторСубъектовРФ
```

#### Для каждого параметра можно задать одно или несколько дополнительных описаний типов параметра

Каждое дополнительное описание начинается с новой строки, затем обязательный дефис, далее список типов параметра далее дефис и текстовое описание.

```1c
// Параметры:
//   Реквизиты - Строка - имена реквизитов, перечисленные через запятую.
//                        Например, "Код, Наименование, Родитель".
//             - Структура, ФиксированнаяСтруктура - в качестве ключа передается
//                        псевдоним поля для возвращаемой структуры с результатом,
//                        а в качестве значения (опционально) фактическое имя поля в таблице.
//                        Если значение не определено, то имя поля берется из ключа.
//             - Массив Из Строка, ФиксированныйМассив Из Строка - имена реквизитов.
```

#### Описание также могут быть заданы с помощью ссылки на функцию-конструктор в формате "см. ПутьКФункции" (англ "see MethodPath")

```1c
// Параметры:
//   ПараметрыУказанияСерий - см. НоменклатураКлиентСервер.ПараметрыУказанияСерий
//   Дубли - см. ОбработкаОбъект.ПоискИУдалениеДублей.ГруппыДублей
//   РеквизитыКомпонент - Массив из см. ВнешниеКомпоненты.РеквизитыКомпоненты
```

При разработке кода, обращающегося к реквизитам конкретного объекта метаданных или формы, можно ссылаться на типы реквизитов этого объекта (формы):

```1c
// Параметры:
//   Запросы - см. Обработка.КонсольЗапросов.ТабличнаяЧасть.Запросы
//   ТипыДанных - см. Обработка.КонсольЗапросов.Реквизит.ДоступныеТипыДанных
//   Вложения - см. Справочник.ШаблоныСообщений.ФормаЭлемента.Вложения
//   КонтактнаяИнформация - см. Документ.ЗаказПокупателя.ФормаДокумента.Объект.КонтактнаяИнформация
```

Если подходящей функции-конструктора не существует и ее невозможно создать, допустимо указывать ссылку на другой метод, при полном совпадении параметров. Или на параметр другой процедуры или функции, например:

```1c
// Параметры:
// См. ПодключаемыеКомандыПереопределяемый.ПриОпределенииКомандПодключенныхКОбъекту
//
Процедура ПриОпределенииКомандПодключенныхКОбъекту(НастройкиФормы, Источники, ПодключенныеОтчетыИОбработки, Команды) Экспорт
...
```

```1c
// Параметры:
//  НастройкиФормы - см. ПодключаемыеКомандыПереопределяемый.ПриОпределенииКомандПодключенныхКОбъекту.НастройкиФормы
//  Источники - см. ПодключаемыеКомандыПереопределяемый.ПриОпределенииКомандПодключенныхКОбъекту.Источники
//  ПодключенныеОтчетыИОбработки - см. ПодключаемыеКомандыПереопределяемый.ПриОпределенииКомандПодключенныхКОбъекту.ПодключенныеОтчетыИОбработки
//  Команды - см. ПодключаемыеКомандыПереопределяемый.ПриОпределенииКомандПодключенныхКОбъекту.Команды
//
Процедура ПриОпределенииКомандПодключенныхКОбъекту(НастройкиФормы, Источники, ПодключенныеОтчетыИОбработки, Команды) Экспорт
...
```

### Секция `Возвращаемое значение` (англ. Returns)

- Обязательная для функций, в процедурах не используется
- **Формат**: `Тип - Описание`
- Описание начинается со строчной буквы

```1c
// Возвращаемое значение:
//  Булево - Истина, если хотя бы одна из переданных ролей доступна текущему пользователю, либо у него есть административные права.
```

Описание можно опускать, если оно очевидно следует из имени функции

```1c
// Возвращаемое значение:
//  Строка
```

При использовании возвращаемого значения составного типа следует каждый тип писать с новой строки и с дефиса. Например:

```1c
// Возвращаемое значение: 
//  - ЛюбаяСсылка - ссылка на предопределенный элемент.
//  - Неопределено - если предопределенный элемент есть в метаданных, но не создан в ИБ.
```

```1c
// Возвращаемое значение:
//  - СправочникСсылка.Пользователи
//  - СправочникСсылка.ВнешниеПользователи
```

### Секция `Пример` (англ. Example)

- Предваряется строкой "Пример:" (англ. "Example:")
- Далее с новой строки пример использования
- Имя процедуры (функции) следует писать вместе с именем общего модуля, в котором она расположена
- Из примера должно быть понятно, что передается на входе и что возвращается на выходе
- Необязательная секция, рекомендуется использовать

```1c
// Пример:
//  СтроковыеФункцииКлиентСервер.ПодставитьПараметрыВСтроку(НСтр("ru='%1 пошел в %2'"), "Вася", "Зоопарк") = "Вася пошел в Зоопарк"
```

### Секция `Варианты вызова` (англ. Сall options)

- Использовать только если сразу несколько параметров имеют дополнительные типы
- Содержить описания возможных вариантов вызова функции с различными комбинациями типов параметров
- Секция начинается фразой "Варианты вызова:" с новой строки
- Затем идут описания вариантов, каждое начинается с новой строки, в формате `ИмяФункции(Тип1, Тип2) - текстовое описание варианта`

```1c
// ...
//
// Параметры:
//   Параметр1 - Тип11, Тип12        - ...
//   Параметр2 - Тип21, Тип22, Тип23 - ...
//
// Варианты вызова:
//   УниверсальнаяПроцедура(Тип11, Тип21) - описание ...
//   УниверсальнаяПроцедура(Тип12, Тип22) - описание ...
//   УниверсальнаяПроцедура(Тип11, Тип23) - описание ...
//
Процедура УниверсальнаяПроцедура(Параметр1, Параметр2) Экспорт
...
```

## Примеры описания процедур и функций

### Пример описания функции с одним параметром

```1c
// Определяет доступность ролей ИменаРолей текущему пользователю,
// а также доступность административных прав.
//
// Параметры:
//   ИменаРолей - Строка - имена ролей, доступность которых проверяется, разделенные запятыми.
//
// Возвращаемое значение:
//   Булево - Истина, если хотя бы одна из переданных ролей доступна текущему пользователю,
//   либо у него есть административные права.
//
// Пример:
// Если РолиДоступны("ИспользованиеРассылокОтчетов,ОтправкаПоПочте") Тогда ...
//
Функция РолиДоступны(ИменаРолей) Экспорт
```

### Пример описания процедуры без параметров

```1c
// В обработчике события ПередЗаписью документа выполняется;
// - очистка табличной части услуги, в случае если указан договор с комиссионером;
// - проверка заполнения реквизита ЕдиницаИзмеренияМест табл. части Товары;
// - синхронизация с "подчиненным" счетом-фактурой;
// - заполнение склада и заказа покупателя в табличных частях Товары и ВозвратнаяТара;
// - удаление неиспользуемых строк табличной части "Серийные номера";
// - заполнение переменной модуля объекта УдалятьДвижение.
//
Процедура ПередЗаписью() 
...
```

## Использование Context7 для дополнительной информации

Для получения актуальной информации по документированию методов в 1С используйте Context7 (доступен через MCP):

### Основные команды Context7

**Поиск библиотек 1С:**

```json
user-context7-resolve-library-id
query: "1C Enterprise Development Tools документация"
libraryName: "1C:Enterprise Development Tools"
```

**Запрос документации:**

```json
user-context7-query-docs
libraryId: "/1c-company/v8-code-style"
query: "документирующие комментарии параметры примеры"
```

### Полезные запросы

- `документирующие комментарии методы параметры возвращаемые значения примеры`
- `стандарты документирования кода 1С`
- `примеры документирующих комментариев экспортных функций`
- `правила типизации в комментариях 1С`

### Рекомендуемые ресурсы

- **1C Code Style V8** (`/1c-company/v8-code-style`) - официальные правила кодирования
- **1C Enterprise Knowledge Base** (`/websites/1c-dn_library`) - общая документация 1С

Context7 предоставляет актуальные примеры и стандарты непосредственно из официальных источников 1С.
