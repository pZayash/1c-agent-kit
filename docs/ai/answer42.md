# Answer42 — UI-driver 1С через клиент тестирования

Канон работы с [Answer42](https://gitlab.com/platform42/answer42-mcp) —
локальным MCP-сервером, который управляет UI 1С:Предприятия через клиент
тестирования. Эксплуатация инструмента (установка, `.env`, сервис, smoke) —
[`tools/answer42/README.md`](../../tools/answer42/README.md).

## Когда применять

- Нужно проверить **живую форму** в 1С:Предприятии: открыть, кликнуть, заполнить,
  прочитать таблицу/динамический список/табличный документ, снять скриншот.
- Веб-клиент (`/web-test`, субагент `tester`) не даёт сценария: нестабильный
  UI, отличия web-версии от тонкого клиента, нужны `/Execute`/`/C`, печать,
  системные диалоги.
- Нужна доказательная запись: `recording_start`/`recording_capture`/`recording_stop`
  собирают аннотированные слайды и `recording.pdf`.

Не применять как замену MCP-серверу ИБ (`dev_dt`): данные, метаданные, запросы и
BSL — там. Answer42 — про **UI**, не про быстрый доступ к данным.

## Как это работает

1. MCP-клиент (агент) → Answer42 → WebSocket bridge → 1С test-manager.
2. Test-manager управляет 1С test-client через API `ТестируемоеПриложение`.
3. Test-client открывает целевую ИБ; действия идут через API клиента, не через
   WinAPI/X11. WinAPI нужен только для скриншотов и геометрии окна.

`start_session` поднимает файловые базы менеджера и (для self-test) демо-клиента,
подбирает порты, при наличии `ibsrv` публикует их через автономный сервер. Клиент
подключается к `base_url`: web-публикация → `/WS`; путь к файловой ИБ → `/F`
(файловую базу, уже открытую сервером/публикацией, так подключать не надо —
будет конфликт блокировки).

## Рабочий цикл агента

1. `start_session(session_id=…, base_url=…, idle_timeout_minutes=…)` — логин/пароль
   не передавать, они берутся из credential-стора по `base_url`.
2. `ui_tree(profile="navigation")` — структура активного окна; дальше не угадывать
   имена, а искать в дереве (`find_object`, `ui_tree(name=…/title=…/type=…)`).
3. Действие: `open_navigation_link("e1cib/list/Документ.…")`, `click_button`,
   `set_field_value`, таблицы (`table_rows`, `table_goto_row`, `table_set_field`),
   динамические списки (`dynamic_list_*`).
4. Чтение результата: `user_messages`, `current_error_info`, `form_state`,
   `field_value_text`, `table_rows`; при потребности — `screenshot`.
5. `stop_session(session_id=…, clean_data=True)` — всегда, иначе процессы и
   временные базы остаются жить.

Правила:

- После каждого действия **проверять фактическое состояние** формы, а не считать
  команду успешной по факту вызова.
- Не объявлять UI-задачу выполненной без состояния формы, скриншота или записи.
- Большие снимки `ui_tree`: `delivery="resource"` + точечные
  `ui_tree_resource_search`/`get_node`/`children`/`diff` вместо чтения всего
  дерева.
- Профили `ui_tree`: `navigation` (по умолчанию, без данных), `diagnostic`
  (с панелями команд), `data` (с представлениями данных), `full`.
- `session_id` — уникальный на поток (`ui-<тема>`), не переиспользовать между
  задачами: до 0.5.13 занятый id мёртвой сессии не освобождался сам. Перед
  `start_session` — `sessions_list` (отдаёт `base_url` и `*_alive`), при
  сомнении — `session_status`.

## Безопасность

- Секреты — только в credential-сторе вне репозитория; в tool-call логин/пароль
  не передавать (аргументы видны агенту и попадают в логи чата).
- `--dev-tools` (регистрирует `dev_eval` = произвольный BSL) не включать.
- `credentials_list` не выдавать агенту (список URL-шаблонов).
- В боевой ИБ по умолчанию — только чтение; запись/проведение — по явной задаче
  оператора.

## Ограничения и известные дефекты

- **Минимальная поддерживаемая версия — 0.5.13.** В ней сборщик сирот работает
  и в HTTP-режиме, плюс есть авто-очистка каталогов сессий: занятые `session_id`
  и `%TEMP%\answer42\sessions\<id>` освобождаются сами. До 0.5.13 у
  HTTP-сервиса накапливались мёртвые сессии (симптомы: чужие окна 1С на другой
  публикации, `Неверно задана навигационная ссылка`, «занят id»); лечение —
  `session_id` на поток + pre-flight `sessions_list` + `stop_session` по
  залипшему id. Проверка версии — `answer42.sh check` / `answer42.ps1 check`.
- **Пустой текст ошибки tool-call** — признак сборки старше 0.5.7 (MCP-SDK 2.x
  сохраняет текст только у `ToolError`). С 0.5.7 upstream сам разворачивает
  `__cause__`/`__context__` (`_visible_tool_error`) и отдаёт сообщение 1С +
  `client_diagnostics`; отдельный форк-патч не нужен. Пустой текст ⇒ проверить
  версию и обновить сборку, а не искать «не тот бинарь». Для диагностики —
  `current_error_info`, `user_messages` и лог сервера. Не трактовать пустой
  текст как «неизвестный сбой платформы».
- Форма «Изменить форму» автоматизируется частично.
- Скриншот без геометрии окна уходит в `fallback: full_display`.
- **Параллельные сессии и рабочий стол.** На текущем рабочем столе окна сессий
  перекрываются, а `screenshot` ищет окно по заголовку/площади без привязки к
  сессии — кадр может прийти из чужой сессии (и авто-maximize развернёт не ту).
  Лечение — `ONEC_MCP_WINDOWS_DESKTOP=hidden`: на каждую сессию свои скрытые
  рабочие столы, захват через `PrintWindow`, окна не видны и фокус не крадётся.
- **Несколько мониторов.** Кадр берётся по прямоугольнику окна в координатах
  виртуального стола — работает на любом мониторе; но при старте сессии окно
  разворачивается на основном мониторе. При масштабе монитора ≠100% первый
  скриншот в жизни процесса может быть смещён (mss включает DPI-awareness после
  чтения геометрии), дальше — корректно.

## Связка с тестированием

- Быстрая массовая регрессия через браузер — `/web-test` + субагент `tester`.
- Точечная проверка живого клиента и доказательства — Answer42.
- Требования к автотестам — [testing.md](testing.md).
