# Форматирование Markdown файлов

## Обзор

Этот документ содержит правила форматирования markdown-файлов в потребителе
kit (пилот и другие проекты).

## Автоматическое применение

Правила форматирования — этот файл. Overlay kit ставит
`.cursor/rules/markdown-formatting.mdc` (alwaysApply) со ссылкой сюда.
Раскладка папок `docs/`: [docs-layout.md](docs-layout.md).

## Проверка соответствия

После создания или редактирования `.md` обязательно запускайте `markdownlint`.

`markdownlint` запускайте напрямую, без `rtk`.

Рекомендуемая команда проверки одного файла: `npx markdownlint путь/к/файлу.md`.

Неправильно: `rtk npx markdownlint путь/к/файлу.md`.

## Кодовые блоки

### Указание языка (MD040)

Все огражденные кодовые блоки должны иметь указанный идентификатор языка.

**Правильно:**
```1c
// Код с указанным языком
Процедура Пример() Экспорт
КонецПроцедуры
```

**Неправильно:**
```
Код без указания языка
```

**Обоснование**: Идентификаторы языка включают подсветку синтаксиса и улучшают читаемость.

### Код 1C:Предприятие

**Важно**: Кодовые блоки, содержащие код 1C:Enterprise (BSL), должны использовать идентификатор языка `1c`, а не `bsl`.

**Правильно:**
```1c
Процедура Тест_Пример() Экспорт
    // Код на языке 1С:Предприятие
КонецПроцедуры
```

**Обоснование**: Идентификатор `1c` обеспечивает лучшую подсветку синтаксиса и отображение в превью markdown по сравнению с `bsl`.

### Жесткие табуляции (MD010)

Не используйте жесткие табуляции в файлах markdown. Заменяйте все символы табуляции пробелами.

**Правильно:**
```1c
|   Документ.ПоступлениеНаСчет КАК ТаблицаДокументов
|       ВНУТРЕННЕЕ СОЕДИНЕНИЕ Документ.ПоступлениеНаСчет.РасшифровкаПлатежа КАК РасшифровкаПлатежаТС
```

**Неправильно:**
```1c
|	Документ.ПоступлениеНаСчет КАК ТаблицаДокументов  // Символ табуляции
|		ВНУТРЕННЕЕ СОЕДИНЕНИЕ ...                      // Символы табуляции
```

**Обоснование**: Жесткие табуляции могут вызвать несогласованное форматирование в разных редакторах и платформах.

## Заголовки

### Конечная пунктуация (MD026)

Заголовки не должны заканчиваться знаками препинания, такими как двоеточия (:), точки с запятой (;).

**Правильно:**
```
#### Правильный подход
#### Рекомендации по псевдонимам
```

**Неправильно:**
```
#### Правильный подход:
#### Рекомендации по псевдонимам:
```

**Обоснование**: Конечная пунктуация в заголовках считается плохим стилем и может мешать структуре документа.

## Структура файла

### Финальный перевод строки (MD047)

Все файлы markdown должны заканчиваться одним символом перевода строки.

**Правильно:** Файл заканчивается на `\n`

**Неправильно:** Файл заканчивается без перевода строки

**Обоснование**: Файлы, заканчивающиеся переводами строк, следуют конвенциям Unix и предотвращают проблемы с системами контроля версий.

## Чекбоксы в списках

Не допускаются ведущие пробелы перед маркером списка для чекбоксов в файлах markdown. Чекбокс должен быть написан как `- [ ]` или `- [x]`, где дефис (`-`) является первым непробельным символом в строке (вложение допускается через правильный отступ, но не через произвольные ведущие пробелы).

**Обоснование**: Неправильно отступленные чекбоксы могут вызвать проблемы при определении задач TODO.

## Ссылки на файлы проекта

Канон всех форматов (code citation, markdown, `#L`, agent-slot, антипаттерны):
[project-file-links.md](project-file-links.md).

Кратко для `.md` в репозитории:

- `[label](path)` — путь UTF-8, **без** percent-encoding кириллицы;
- строка: `[file.bsl:42](conf/…/file.bsl#L42)`;
- в чате агента для фрагмента кода — code citation `` ```start:end:path `` (см. канон).

**Правильно:**

- `[skillopt-пилот-задание.md](docs/ai/skillopt-пилот-задание.md)`
- `[ObjectModule.bsl:4794](conf/Documents/РасходнаяНакладная/Ext/ObjectModule.bsl#L4794)`

**Неправильно:**

- `[…](docs/ai/skillopt-%D0%BF%D0%B8%D0%BB%D0%BE%D1%82-…md)` — encoded URL
- голый `conf/CommonModules/%D1%8F%D1%8F_…/Module.bsl` без `[]()`
- `` `conf/…/file.bsl` `` в ответе агента вместо markdown-ссылки

**Обоснование**: Cursor (в т.ч. agent-slot) не открывает encoded и «голые» пути как file-links.

## Имена новых файлов — только латиница

**Новые файлы и каталоги**, создаваемые агентом, именовать **только латиницей** (английскими словами, kebab-case или snake_case). Кириллицу в имена новых файлов **не вставлять**.

**Правильно:**

- `docs/ai/skillopt-pilot-task.md`
- `handoffs/skillopt-pilot/r2-request.md`
- `tools/skillopt-mine-cases/mine_query_rule.py`

**Неправильно (для новых файлов):**

- `docs/ai/skillopt-пилот-задание.md`
- `handoffs/scenarii/обмен-с-приор.md`

**Обоснование**: Рендерер markdown-ссылок в Claude Code для VS Code часто percent-encode-ит кириллицу автоматически (см. правило про ссылки выше). Это поведение рендерера, не агента — починить нельзя. Латинские имена гарантированно кликабельны. Латинские имена — страховка на случай когда правило про ссылки нарушается рендерером.

**Исключения:**

- **Существующие** файлы с кириллицей в имени (`docs/ai/skillopt-датасеты.md`, `docs/ai/изменение-типовых-форм.md`, `docs/ai/код-отчёты.md` и т.п.) — **не переименовывать без явной просьбы**. Переименование ломает ссылки и git-историю.
- **Конф-объекты 1С** в `conf/` (`conf/Documents/РасходнаяНакладная/...`) — кириллица обязательна по конвенции платформы 1С. Правило не применяется.
- **Содержимое файлов** (тело markdown, BSL, комментарии) — по-прежнему на русском по общему правилу проекта (см. `CLAUDE.md`). Только имя файла — латиницей.
