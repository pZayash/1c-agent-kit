# Спецификация `autotest.scenario.json`

Файл `autotest.scenario.json` лежит рядом с корневым XML текущего `EPF/ERF`.

## Назначение

- `append` — дополняет автоопределённые шаги;
- `replace` — полностью заменяет автошаги;
- позволяет явно задать неоднозначные действия, которые нельзя надёжно вывести только по `BSL + Form.xml`.

## Формат файла

```json
{
  "mode": "append",
  "steps": [
    {
      "kind": "set_form_requisite",
      "name": "Организация",
      "value": {
        "type": "reference",
        "metadata": "Справочник.Организации",
        "selector": {
          "kind": "by_code",
          "value": "000001"
        }
      }
    },
    {
      "kind": "call_form_handler",
      "name": "ОрганизацияПриИзменении"
    },
    {
      "kind": "set_form_requisite",
      "name": "ПериодНачало",
      "value": {
        "type": "date",
        "value": "2026-01-01"
      }
    },
    {
      "kind": "call_command",
      "name": "Сформировать"
    },
    {
      "kind": "call_object_method",
      "name": "ПроверитьПараметры",
      "args": [
        {
          "type": "string",
          "value": "Тест"
        },
        {
          "type": "number",
          "value": 1
        }
      ]
    }
  ]
}
```

## Корневые поля

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `mode` | `append` \| `replace` | да | Режим применения сценария |
| `steps` | массив | да | Упорядоченный список шагов |

## Поддерживаемые `kind`

### `call_object_method`

Вызывает экспортный метод модуля объекта.

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `name` | строка | да | Имя экспортного метода |
| `args` | массив значений | нет | Аргументы вызова |
| `transaction` | `rollback` | нет | Выполнить шаг внутри транзакции и в конце всегда вызвать `ОтменитьТранзакцию()` |

### `call_form_handler`

Вызывает обработчик формы, если он может быть вызван безопасно.

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `name` | строка | да | Имя процедуры формы |
| `element` | строка | нет | Имя элемента формы, которое будет передано первым параметром |
| `args` | массив значений | нет | Явные параметры вызова; если указаны, имеют приоритет над `element` |
| `transaction` | `rollback` | нет | Выполнить обработчик в откатываемой транзакции, если раннер может безопасно ей владеть |

### `call_command`

Вызывает команду формы или её обработчик.

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `name` | строка | да | Имя команды |
| `args` | массив значений | нет | Явные параметры вызова обработчика команды |
| `transaction` | `rollback` | нет | Выполнить шаг внутри транзакции и после проверки отменить изменения |

### `set_form_requisite`

Устанавливает тестовое значение реквизиту формы.

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `name` | строка | да | Имя реквизита формы |
| `value` | значение | да | Значение в типизированном виде |
| `handler` | строка | нет | Явный обработчик формы, который нужно вызвать после установки значения |
| `element` | строка | нет | Имя элемента формы для передачи в обработчик после изменения |

По умолчанию после `set_form_requisite` раннер пытается вызвать обработчик `<ИмяРеквизита>ПриИзменении`, если он существует. Это нужно для более реалистичной эмуляции ручного ввода пользователя.

Для ссылочных реквизитов раннер сначала разрешает `value` в реальный объект допустимого типа, потом устанавливает реквизит и только после этого вызывает обработчик изменения.

Если последующий обработчик изменения или команда выполняет запись в базу, раннер должен предпочитать прогон в транзакции с откатом, а не молчаливый `skipped`.

### `assert`

Проверяет условие и записывает результат в лог. Не выполняет действий, только читает текущее состояние.

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `target` | строка | да | Что проверять: `form_requisite`, `object_method_result`, `table_row_count` |
| `name` | строка | да | Имя реквизита, метода или табличной части |
| `operator` | строка | да | Оператор сравнения: `equals`, `not_equals`, `greater`, `less`, `contains`, `not_empty`, `is_empty`, `type_is` |
| `expected` | значение | нет | Ожидаемое значение в типизированном виде; не требуется для `not_empty` и `is_empty` |
| `args` | массив значений | нет | Аргументы вызова метода; только для `target = "object_method_result"` |
| `message` | строка | нет | Пояснение, которое попадёт в лог при провале |

Варианты `target`:

- `form_requisite` — читает значение реквизита формы и сравнивает с `expected`; выполняется на клиенте;
- `object_method_result` — вызывает экспортный метод модуля объекта и сравнивает результат с `expected`; выполняется на сервере;
- `table_row_count` — считает количество строк табличной части формы и сравнивает с `expected`; выполняется на клиенте.

Статус в логе:

- `assert_<name> | ok | expected: X, actual: X`
- `assert_<name> | fail | expected: X, actual: Y | <message>`

Статус `fail` — это не `error`: шаг выполнен без исключения, но проверка не прошла.

Пример:

```json
{
  "kind": "assert",
  "target": "form_requisite",
  "name": "Организация",
  "operator": "not_empty",
  "message": "Организация должна быть заполнена после вызова Сформировать"
}
```

### `add_table_row`

Добавляет строку в табличную часть формы и заполняет указанные колонки. Выполняется на клиенте.

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `table` | строка | да | Имя табличной части формы (реквизит типа `ДанныеФормыКоллекция`) |
| `values` | объект | да | Словарь `ИмяКолонки → значение` в типизированном виде |
| `transaction` | `rollback` | нет | Выполнить шаг внутри транзакции и отменить |

Раннер выполняет: `НоваяСтрока = Объект.<table>.Добавить()`, затем заполняет колонки по `values`. Для ссылочных значений колонок используются те же правила разрешения, что и для `set_form_requisite`.

Пример:

```json
{
  "kind": "add_table_row",
  "table": "Товары",
  "values": {
    "Номенклатура": { "type": "reference", "metadata": "Справочник.Номенклатура", "selector": { "kind": "any" } },
    "Количество": { "type": "number", "value": 10 },
    "Цена": { "type": "number", "value": 100 }
  }
}
```

### `clear_table`

Очищает все строки табличной части формы. Выполняется на клиенте.

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `table` | строка | да | Имя табличной части формы |

Пример:

```json
{
  "kind": "clear_table",
  "table": "Товары"
}
```

### `fill_table`

Очищает табличную часть и заполняет её указанными строками за один шаг. Выполняется на клиенте. Эквивалент `clear_table` + несколько `add_table_row`, но в логе отражается как один шаг.

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `table` | строка | да | Имя табличной части формы |
| `rows` | массив объектов | да | Каждый элемент — словарь `ИмяКолонки → значение` |
| `transaction` | `rollback` | нет | Выполнить шаг внутри транзакции и отменить |

Пример:

```json
{
  "kind": "fill_table",
  "table": "Товары",
  "rows": [
    { "Номенклатура": { "type": "reference", "metadata": "Справочник.Номенклатура", "selector": { "kind": "any" } }, "Количество": { "type": "number", "value": 5 } },
    { "Номенклатура": { "type": "reference", "metadata": "Справочник.Номенклатура", "selector": { "kind": "any" } }, "Количество": { "type": "number", "value": 10 } }
  ]
}
```

## Формат значения

```json
{
  "type": "string | number | boolean | null | date | empty_string | reference",
  "value": "..."
}
```

Правила:

- `string` — обычная строка;
- `number` — число;
- `boolean` — `true` или `false`;
- `null` — `Неопределено`;
- `date` — ISO-строка `YYYY-MM-DD`;
- `empty_string` — явная пустая строка.

### Ссылочное значение

Для `type = "reference"` используй отдельный формат:

```json
{
  "type": "reference",
  "metadata": "Справочник.Организации",
  "selector": {
    "kind": "any | by_name | by_code | by_ref",
    "value": "..."
  }
}
```

Правила:

- `metadata` — обязательный полный тип метаданных, например `Справочник.Организации`, `Документ.ЗаказКлиента`;
- `selector.kind = "by_name"` — ищи объект по наименованию или представлению;
- `selector.kind = "by_code"` — ищи объект по коду, номеру или другому стандартному идентификатору списка;
- `selector.kind = "by_ref"` — используй переданную строку ссылки как явный идентификатор объекта;
- `selector.kind = "any"` — выбери любой доступный объект допустимого типа безопасным запросом к данным;
- если реквизит допускает несколько ссылочных типов, `metadata` должен указывать конкретный тип, который нужно подставить;
- если пользователь не указал объект, а выбор не важен для сценария, предпочитай `any` вместо молчаливого `skipped`.

## Правила для шагов с записью

- Запись в информационную базу сама по себе не запрещает автошаг.
- Если побочный эффект можно изолировать транзакцией ИБ, шаг должен выполняться внутри `НачатьТранзакцию()` / `ОтменитьТранзакцию()`.
- Если шаг явно помечен `transaction = "rollback"`, раннер обязан либо выполнить его с откатом, либо записать `skipped` с конкретной причиной, почему откат нельзя гарантировать.
- Перед началом rollback-шага раннер должен проверить `ТранзакцияАктивна()`. Если уже активна чужая транзакция, нельзя безусловно откатывать её ради теста.
- Необратимые побочные эффекты вне транзакции, например файлы, внешние HTTP/COM-вызовы, почта и фоновые задания, не маскируй под rollback-шаги: они остаются `skipped` или выносятся в отдельную ручную подготовку.

## Что запрещено в `v1.1`

- Неизвестные `kind` (поддерживаются: `call_object_method`, `call_form_handler`, `call_command`, `set_form_requisite`, `assert`, `add_table_row`, `clear_table`, `fill_table`).
- Неявные сложные типы без правил преобразования.
- Шаги, которые требуют интерактивного выбора файла, окна подтверждения или модального ввода.
- Пропуск ссылочного реквизита только по причине того, что он ссылочный.
- Пропуск шага только по причине записи в информационную базу, если запись можно безопасно проверить в транзакции с откатом.
- Попытка скрыть необратимую небезопасную ветку как обычный rollback-шаг: такие действия должны оставаться `skipped` либо быть вынесены в явное ручное описание.
- Использование `assert` с `target = "object_method_result"` для методов с побочными эффектами: assert должен только читать состояние или вызывать чистые функции.
