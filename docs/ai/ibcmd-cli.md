# ibcmd — CLI-грабли

Короткий справочник по утилите `ibcmd` (автономный сервер / управление ИБ).
Для load-changed-files — см. [load-config-to-dev.md](load-config-to-dev.md).

## Справка

- `ibcmd help` / `ibcmd <mode> --help` — только **верхнеуровневый** хелп.
- `ibcmd help <mode>` (один аргумент: `infobase`, `config`, `session`…) — хелп
  режима **целиком**, включая подкоманды (`config import files`, `export objects`).
- `ibcmd help "infobase config"` и `--help` внутри подкоманды — НЕ работают,
  выводят общий хелп.
- Консольный вывод — **CP866** под Windows: `… | iconv -f CP866 -t UTF-8`.

## Аутентификация

- Без `-u/-P` ibcmd уходит в интерактивный промпт `Имя пользователя:` и
  **флудит stdout** (мегабайты в фоне). Всегда `-u <user> -P <pwd>` или
  проверять наличие кредов заранее.
- `--db-path` — файловая ИБ (эксклюзивна: ни ibsrv, ни 1cv8, ни второй ibcmd
  не должны держать базу). `--pid=<pid>` — шлюз узла ibsrv (без монополии).
- `--data=<dir>` — рабочий каталог сервера. Дефолт один на учётку Windows и
  заперт `lock.pid` → параллельный ibcmd падает «Ошибка блокировки каталога
  данных сервера». Свой `--data` на воркспейс.

## Импорт конфигурации

- `infobase config import <dir>` — полная загрузка из дампа.
- `infobase config import files --base-dir=<dir> [files…]` — изменённый набор.
  Список: argv-аргументы или **stdin** (по строке на файл, пути относительные
  `--base-dir`, **CP1251** под Windows — UTF-8 список даст «файл не обнаружен»).
- `--partial` — каждый файл списка обязан мапиться на объект метаданных.
  `Configuration.xml` отвергается: «URL … не может быть преобразован в полное
  имя объекта метаданных». Корневой файл грузится **только без `--partial`**
  (changeset: свойства корня, добавление и УДАЛЕНИЕ объектов по ChildObjects —
  список зеркалит состав конфигурации; проверка всей конфигурации, минуты).
- Кварк: одиночный `Configuration.xml` единственной строкой stdin-списка
  отвергается и без `--partial` — через argv или в списке ≥2 файлов работает.
- Новый объект без `Configuration.xml` в списке → «нельзя добавлять объекты
  метаданных без загрузки родительского объекта».
- `--no-check` глушит **post-check** метаданных, но НЕ load-time валидацию
  (битые формы «Неверный путь к данным» всё равно валят прогон — прятать их
  файлы на время загрузки).
- Падение **до** любых проверок (`rc≠0`, stderr пуст, свежий `*.mdmp`
  в `%LOCALAPPDATA%\1C\1cv8\dumps\`, счётчик `[N/M]` не растёт) — битый файл
  разбора: объект не в формате дампа. `--no-check` не лечит; искать линтером
  (см. [load-config-to-dev.md](load-config-to-dev.md) § «Загрузка виснет молча»).
- `config apply --dynamic=disable --session-terminate=force` на базе, живущей
  на автономном сервере, **роняет `ibsrv.exe` в mdmp**: force-терминейт уносит
  сервер, а не только клиентские сеансы. Снимать сеансы явно:
  `ibcmd session list --pid=<pid>` → `ibcmd session terminate --pid=<pid>`.
- `export` обратно: `infobase config export <dir>` — весь дамп;
  `export objects <Объект> --out=<dir>` — **один объект** (напр. `Configuration`)
  — дешёвый способ сравнить ИБ с диском. `export status --base <ConfigDumpInfo>`
  сравнивает **configVersion** (счётчики), не контент: `M: all` ≠ расхождение.
