# Ловушки платформы 1С

Краткий справочник типовых ошибок платформы. Используй при ревью, исправлении
багов, доработке проведения, фоновых операций и клиент-серверного кода.

## Проверка заполненности

Не проверяй ссылки через сравнение с `Неопределено`: пустая ссылка пройдет такую
проверку как заполненная.

```1c
Если ЗначениеЗаполнено(Контрагент) Тогда
    // Контрагент не пустой.
КонецЕсли;
```

Для реквизитов формы со ссылочным/составным типом — скопируй значение в локальную
переменную и проверяй её, чтобы не дёргать свойство платформы повторно:

```1c
ТекущийКонтрагент = Объект.Контрагент;

Если ЗначениеЗаполнено(ТекущийКонтрагент) Тогда
    // ...
КонецЕсли;
```

## Длительные операции

Операции дольше нескольких секунд не должны блокировать клиент. Используй
подсистему БСП `ДлительныеОперации`, а не прямой запуск фонового задания.

```1c
Параметры = Новый Структура;
Параметры.Вставить("ДатаНачала", ДатаНачала);
Параметры.Вставить("ДатаОкончания", ДатаОкончания);

ДлительнаяОперация = ДлительныеОперации.ВыполнитьФункцию(
                          ПараметрыВыполнения,
                          "Отчеты.ПродажиПоПериоду.СформироватьДанныеНаСервере",
                          Параметры   );
```

`ИмяВыполняемогоМетода` — формат `ИмяОбщегоМодуля.ИмяФункции` или
`Тип.ИмяОбъекта.ИмяМетода` (без префикса `ОбщийМодуль.`). На клиенте —
`ДлительныеОперацииКлиент.ОжидатьЗавершение` для опроса статуса. Не передавай в
фоновое задание адрес во временном хранилище, привязанный к сессии формы —
передавай сериализуемые параметры; результат клади в хранилище изнутри задания.

## Фоновое задание из внешней обработки (БСП)

`ДлительныеОперации` выполняется на сервере. Если обработка открыта через
«Файл → Открыть» (внешняя `*.epf`, не из справочника
`ДополнительныеОтчетыИОбработки`), БСП не найдёт её на сервере —
`ВыполнитьВФоне` падает («Метаданные не найдены» / «Не удалось получить
обработку на сервере»).

**Решение: скопировать бинарник обработки на сервер через временное хранилище.**

Помещение файла обработки при открытии:

```1c
&НаКлиенте
Процедура ПриОткрытии(Отказ)
    Если ЭтоВнешняяОбработка() Тогда
        ОписаниеОповещения = Новый ОписаниеОповещения(
            "ОбработатьРезультатПомещенияФайлаОбработки", ЭтотОбъект);
        НачатьПомещениеФайлов(ОписаниеОповещения,
            ИмяФайлаОбработки(), Ложь, УникальныйИдентификатор);
    КонецЕсли;
КонецПроцедуры

&НаКлиенте
Процедура ОбработатьРезультатПомещенияФайлаОбработки(ПомещенныеФайлы, ОбработчикЗавершения) Экспорт
    Если ПомещенныеФайлы <> Неопределено Тогда
        ХранениеФайлаОбработки = КопияОбработкиНаСервере(ПомещенныеФайлы[0].Хранение);
    КонецЕсли;
КонецПроцедуры

&НаСервере
Функция КопияОбработкиНаСервере(Хранение)
    Результат = ПолучитьИмяВременногоФайла();
    ДвоичныеДанные = ПолучитьИзВременногоХранилища(Хранение);
    ДвоичныеДанные.Записать(Результат);
    Возврат Результат;
КонецФункции
```

Запуск фонового задания:

```1c
&НаСервере
Функция НачатьВыполнениеФоновогоЗаданияНаСервере()
    ЭтоВнешняяОбработка = ЭтоВнешняяОбработка();
    Если ЭтоВнешняяОбработка Тогда
        ИмяОбработки = ХранениеФайлаОбработки;
    Иначе
        ИмяОбработки = РеквизитФормыВЗначение("Объект").Метаданные().ПолноеИмя();
    КонецЕсли;

    ПараметрыЗадания = Новый Структура;
    ПараметрыЗадания.Вставить("ИмяОбработки", ИмяОбработки);
    ПараметрыЗадания.Вставить("ИмяМетода", "<имя процедуры в модуле объекта>");
    ПараметрыЗадания.Вставить("ПараметрыВыполнения", ПараметрыВыполненияОбработки);
    ПараметрыЗадания.Вставить("ЭтоВнешняяОбработка", ЭтоВнешняяОбработка);

    ПараметрыВыполнения = ДлительныеОперации.ПараметрыВыполненияВФоне(УникальныйИдентификатор);
    ПараметрыВыполнения.НаименованиеФоновогоЗадания = "<описание задания>";
    ПараметрыВыполнения.ЗапуститьВФоне = Истина;

    Возврат ДлительныеОперации.ВыполнитьВФоне(
        "ДлительныеОперации.ВыполнитьПроцедуруМодуляОбъектаОбработки",
        ПараметрыЗадания, ПараметрыВыполнения);
КонецФункции
```

Обход safe-mode внутри фонового задания — свежий экземпляр обработки без
безопасного режима:

```1c
Процедура ОбработкаДанныхВФоне(Параметры, АдресРезультата) Экспорт
    ЧастиИмени = СтрРазделить(ЭтотОбъект.Метаданные().ПолноеИмя(), ".");
    ЭтоВнешняяОбработка = (ВРег(ЧастиИмени[0]) = "ВНЕШНЯЯОБРАБОТКА");
    Если ЭтоВнешняяОбработка Тогда
        ОбработкаОбъект = ВнешниеОбработки.Создать(
            ЭтотОбъект.ИспользуемоеИмяФайла, Ложь,
            ОбщегоНазначения.ОписаниеЗащитыБезПредупреждений());
        Результат = ОбработкаОбъект.ОбработкаДанных(...);
    Иначе
        Результат = ОбработкаДанных(...);
    КонецЕсли;
    ПоместитьВоВременноеХранилище(Результат, АдресРезультата);
КонецПроцедуры
```

Ограничения:

- Процедура фонового задания не использует реквизиты формы и ТЧ обработки —
  всё через параметры.
- Серверная копия живёт во временном файле — держи путь в реквизите формы
  (`ХранениеФайлаОбработки`) до завершения длительной операции.

Требует БСП 3.0+, платформа 8.3.13+.

## Временное хранилище

`ВременноеХранилище` - не объект с методами. Используй глобальные функции
платформы.

```1c
Адрес = ПоместитьВоВременноеХранилище(Данные, УникальныйИдентификатор);
Данные = ПолучитьИзВременногоХранилища(Адрес);
```

## Транзакции в обработчиках записи

В `ПередЗаписью`, `ПриЗаписи`, обработчиках проведения и подписках записи не
открывай вложенную транзакцию без отдельной причины: платформа уже выполняет
запись объекта в транзакции.

Если нужна внешняя транзакция, открывай ее в вызывающем коде:

```1c
НачатьТранзакцию();

Попытка
    Документ.Записать(РежимЗаписиДокумента.Проведение);
    ЗафиксироватьТранзакцию();
Исключение
    ОтменитьТранзакцию();
    ВызватьИсключение;
КонецПопытки;
```

Внутри транзакции не вызывай диалоги, сетевые сервисы и длительные операции.

## Копирование объектов и табличных частей

Для таблиц значений используй `Скопировать()`. Для структур — копируй циклом
(метода `Скопировать()` нет). Для документов создавай новый объект и явно
копируй нужные реквизиты и табличные части.

```1c
// Таблица значений.
КопияТаблицы = ИсходнаяТаблица.Скопировать();

// Структура.
КопияСтруктуры = Новый Структура;
Для Каждого КлючИЗначение Из ИсходнаяСтруктура Цикл
    КопияСтруктуры.Вставить(КлючИЗначение.Ключ, КлючИЗначение.Значение);
КонецЦикла;

// Документ как новый объект.
НовыйДокумент = Документы.РеализацияТоваровУслуг.СоздатьДокумент();
ЗаполнитьЗначенияСвойств(   НовыйДокумент, ИсходныйДокумент,
                            ,
                            "Номер,Дата,ПометкаУдаления,Проведен"   );
НовыйДокумент.Товары.Загрузить(ИсходныйДокумент.Товары.Выгрузить());
```

Не копируй стандартные реквизиты `Номер`, `Дата`, `ПометкаУдаления`, `Проведен`,
если создается новый документ — иначе платформа может попытаться перезаписать
исходный.

## Время на сервере

На сервере используй `ТекущаяДатаСеанса()`, а не `ТекущаяДата()`: кластер и
часовой пояс сеанса могут отличаться.

```1c
ТекущаяДатаДокумента = ТекущаяДатаСеанса();
```

## Поиск в коллекциях

Линейный поиск внутри цикла быстро превращается в `O(n^2)`.

- До примерно 100 элементов допустимы `Найти()` и `НайтиПоЗначению()`.
- Для больших коллекций или поиска внутри цикла построй индекс на
  `Соответствие`.
- Для таблицы значений с частым поиском используй
  `Таблица.Индексы.Добавить(...)` и `НайтиСтроки()`.

```1c
ИндексПоИНН = Новый Соответствие;

Для Каждого СтрокаКонтрагента Из ТаблицаКонтрагентов Цикл
    ИндексПоИНН.Вставить(СтрокаКонтрагента.ИНН, СтрокаКонтрагента.Контрагент);
КонецЦикла;

Контрагент = ИндексПоИНН.Получить(ИНН);
```

## Внешние компоненты

В тонком и web-клиенте не подключай внешние компоненты синхронно. Используй
асинхронное подключение через `НачатьПодключениеВнешнейКомпоненты` и
`ОписаниеОповещения`.

## Управляемые блокировки

> Дизайн-правила (границы транзакций, порядок блокировок, дедлоки, диагностика) —
> в [locks-and-transactions.md](locks-and-transactions.md). Здесь — краткая
> шпаргалка по рабочему примеру.

При проведении документа ставь управляемую блокировку до чтения данных, которые
затем изменяются движениями. Блокируй регистр, а не документ.

```1c
Блокировка = Новый БлокировкаДанных;

ЭлементБлокировки = Блокировка.Добавить("РегистрНакопления.ТоварыНаСкладах");
ЭлементБлокировки.Режим = РежимБлокировкиДанных.Исключительный;
ЭлементБлокировки.ИсточникДанных = Товары;
ЭлементБлокировки.ИспользоватьИзИсточникаДанных("Номенклатура", "Номенклатура");
ЭлементБлокировки.ИспользоватьИзИсточникаДанных("Склад", "Склад");

Блокировка.Заблокировать();
```

Правила:

- Блокировка живет до конца текущей транзакции.
- Для записи используй `Исключительный`, для согласованных чтений -
  `Разделяемый`.
- Во всех документах соблюдай один порядок блокировки регистров, иначе возможны
  deadlock-и.
- Для диагностики смотри технологический журнал `TLOCK` / `TDEADLOCK`.

## Навигационная ссылка (`e1cib`, `ref`)

Пользователь или чат присылает `e1cib/data/Документ.…?ref=<32 hex>`.
Параметр `ref` — тот же UUID, но **порядок байт платформы** (32 hex **без**
дефисов). В MCP, запросах и BSL — GUID `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`.

Пример (заказ, prod): `ref=980300505691c6db11f1559bb8763b28` ↔
`b8763b28-559b-11f1-9803-00505691c6db`.

Правила для агентов:

1. Не собирать `e1cib/...` вручную из UUID ответа MCP — только
   `navigation_url_get`.
2. Из ссылки пользователя: искать по **номеру, дате, контрагенту**; в `query_post`
   можно передать 32 hex в `_ref` (нормализация
   на сервере). Пустой результат — повторить с GUID из найденной строки.
3. Hex из буфера обмена клиента без конвертации — неверный ключ в коде.

## Пустая дата в дефолте параметра / литерале

Одинарные кавычки в 1С — **литерал даты**, не строки. `''` = пустой литерал даты
→ ошибка компиляции модуля «Неправильная константа типа Дата».

```bsl
// ❌ ошибка компиляции
Процедура Заполнить(пТаблица, пДата = '') Экспорт
// ✅
Процедура Заполнить(пТаблица, пДата = Неопределено) Экспорт
```

Дефолт даты-параметра — `Неопределено`; внутри проверять `ЗначениеЗаполнено(пДата)`.
Строковый литерал — двойные кавычки `""`.

## Программная форма: `Добавить` соседа после `Переместить` типового элемента

При программной сборке формы: если **перенести** типовой (вендорский) элемент в
группу (`Элементы.Переместить` / helper-обёртка), а **затем** `Элементы.Добавить`
рядом декорацию/поле, в некоторых формах (наблюдалось на форке формы документа)
декорация **не создаётся** — без ошибки. Для программно создаваемого нового
элемента (другая форма) тот же код работает.

Решение: **добавлять соседа ДО переноса** типового элемента, а визуальный порядок
задавать отдельно через `Элементы.Переместить(сосед, группа)`. Симптом при
проверке: элемент отсутствует в `getFormState` (см.
[web-test-unf-playbook.md](web-test-unf-playbook.md) § 11).

## Формат числа: ноль выводится пустой строкой

Числовые шаблоны форматирования отдают **пустую строку ровно для нуля**
(проверено на живой ИБ, оба контекста исполнения — клиентский и привилегированный):

| Выражение | Результат |
| --- | --- |
| `Формат(0, "ЧГ=0")` | `""` |
| `Формат(0, "ЧЦ=15; ЧДЦ=0")` | `""` |
| `Формат(0, "ЧН=0")` | `"0"` |
| `Формат(5, "ЧГ=0")` | `"5"` |
| `Строка(0)` | `"0"` |

Симптом: в кодовом отчёте или в тексте письма «пропадают» нули — ячейки и
счётчики выглядят пустыми, а ненулевые значения выводятся нормально.

Правило: где возможен ноль — `Строка(Значение)` (с разделителями групп) или
`Формат(Значение, "ЧН=0")`. Шаблоны `"ЧГ=…"` и `"ЧЦ=…; ЧДЦ=…"` для таких
значений не использовать.

## Реквизит формы «ТаблицаЗначений» — это данные формы, а не `ТаблицаЗначений`

В управляемой форме реквизит, объявленный как `v8:ValueTable` (и/или привязанный к таблице на форме),
в коде модуля ведёт себя как **объект данных формы** (коллекция данных формы), а не как обычная
`ТаблицаЗначений`:

- **Нельзя присвоить реквизиту значение целиком** (`ТаблицаФормы = Таблица` или
  `ТаблицаФормы = Новый ТаблицаЗначений`) — «Нельзя изменять поле, содержащее объект данных формы».
  Заполнять **на месте**: `Очистить()` + `Добавить()` + `ЗаполнитьЗначенияСвойств(НоваяСтрока, СтрокаДанных)`,
  либо разово `ЗначениеВРеквизитФормы(Таблица, "Имя")`.
- **Нельзя передавать реквизит-таблицу в код, ожидающий `ТаблицаЗначений`**: у коллекции данных формы
  нет `Колонки` — падение «Поле объекта не обнаружено (Колонки)» (типовой случай: общий помощник делает
  `Для Каждого Колонка Из Таблица.Колонки Цикл`). Читать значение надо через
  `РеквизитФормыВЗначение("Имя")` — так это и делается в типовом коде.

Живой случай (09.2026, обработка `ФормированиеЦенНоменклатуры`, форма диалога видов цен): сначала
«нельзя изменять поле…» — реквизит присваивали целиком; после «починки» на голом реквизите прилетело
`Поле объекта не обнаружено (Колонки)` — реквизит передали в общий помощник. Правильный идиом в том же
объекте: `РеквизитФормыВЗначение("ТЧНоменклатура")` → работа → `ЗначениеВРеквизитФормы(ТЗ, "ТЧНоменклатура")`.

Статические проверки (BSL/BSLLS) этот класс **не ловят** — нужен живой прогон формы.

## `ПоместитьВоВременноеХранилище` с явным идентификатором — только в форме

`ПоместитьВоВременноеХранилище(<Значение>, <УникальныйИдентификатор>)` использует **идиом формы**:
в общем модуле, тесте или внешней обработке `УникальныйИдентификатор` не определён — вызов падает.
Варианты: `ПоместитьВоВременноеХранилище(<Значение>)` (платформа сама выдаёт адрес) либо
`ПоместитьВоВременноеХранилище(<Значение>, Новый УникальныйИдентификатор(<СтрокаИлиЧисло>))`.

## `ТаблицаЗначений.Скопировать(<Колонки>)` на нашей платформе не принимает ни массив, ни строку

Скопировать таблицу с подмножеством колонок «одним вызовом» не получится: метод не принимает ни `Массив`
имён, ни строку. Рабочий приём: `Копия = Исходная.Скопировать()` без аргументов, затем удалять лишние
колонки **по индексам вниз** (`Для Индекс = Колонки.Количество() - 1 По 0 Шаг -1 Цикл … Колонки.Удалить(Индекс)`).

Живые случаи: 30.09.2026, перенос обмена ценами из мастера в документ `УстановкаЦенНоменклатуры`
(нашлись только рантаймом, статика их не видит).

## `СоздатьЭлемент()` не применяет значение заполнения из метаданных

`Справочники.<Имя>.СоздатьЭлемент()` (и аналоги) **не** подставляет `ЗначениеЗаполнения` реквизитов из
метаданных: реквизит остаётся пустым, хотя при интерактивном создании форма его заполняет. Классический
живой случай (01.10.2026): вид цены, созданный программно из файла, получал пустой `ТипВидаЦен` →
типовая `ПолучитьКартинкуДляВидЦены()` возвращала `Неопределено` → падение типового
`ДобавитьРеквизитыИЭлементыТабличнойЧастиПоВидуЦен` на `ГруппаЦены.КартинкаШапки` («Несоответствие типов»).
Правило: при программном создании объектов явно заполнять реквизиты, у которых в метаданных задано
значение заполнения (проверять по метаданным, а не «по памяти»).

## Команду на форму можно вывести дважды, только создав кнопку с другим именем

`КнопкаКоманды` создаёт элемент формы с именем = имени команды, поэтому **повторно** вставить её на форму
(например, продублировать команду на командную панель) нельзя. Приём: создать кнопку с собственным именем
(в проекте — `яя_формы.КнопкаВМесте`) и разместить её в нужной панели/группе; `Вид = КнопкаКоманднойПанели`
для верхней панели формы. Живое требование (01.10.2026): кнопки обмена ценами с Excel должны быть доступны
на **новом пустом** документе, а не только на странице, до которой надо дойти после выбора видов цен.

## Дерево значений: `ДеревоЗначений` ≠ данные формы дерева

У значения из `ДеревоЗначений` нет методов `ПолучитьЭлементы()` / `ПолучитьРодителя()` — они есть у
`ДанныеФормыДерево`. В `ДеревоЗначений` обход идёт через `Строки` и свойство `Родитель`. Чтобы править дерево
реквизита формы, работать надо так: `РеквизитФормыВЗначение("Имя", Тип("ДеревоЗначений"))` → правки →
`ЗначениеВРеквизитФормы` (живой случай 01.10.2026: отметки видов цен в форме документа «Установка цен»).

## Не присваивать параметру-строке дерева внутри `Пока`

`Пока Строка <> Неопределено Цикл … Строка = Строка.Родитель; КонецЦикла` — присваивание параметру в теле
цикла **не** влияет на условие: платформа проверяет исходный параметр, а не изменённую переменную. Подъём по
дереву делать через локальную переменную (`Текущая = Строка; Пока Текущая <> Неопределено Цикл …`).
