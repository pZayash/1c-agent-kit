# Кликабельные ссылки на файлы проекта

Канон для ответов агентов в **Cursor** (чат, Composer, agent-slot) и для markdown в репозитории.
Краткое правило IDE: [.cursor/rules/project-file-links.mdc](../../.cursor/rules/project-file-links.mdc).

## Зачем

Пути с кириллицей (`conf/CommonModules/яя_…`, `conf/Documents/ЗаказПокупателя/…`) часто
ломаются, если агент или рендерер подставляет **percent-encoding** (`%D1%8F%D1%8F_…`).
Такие ссылки в agent-slot и на хосте **не открываются** по клику.

Примеры **сломанных** ссылок (не кликабельны в Cursor, в т.ч. agent-slot):

```text
conf/CommonModules/%D1%8F%D1%8F_%D0%A3%D1%81%D0%BB%D0%BE%D0%B2%D0%B8%D1%8F%D0%9E%D0%BF%D0%BB%D0%B0%D1%82%D1%8B%D0%9F%D1%80%D0%BE%D0%B4%D0%B0%D0%B6%D0%B8/Ext/Module.bsl
conf/CommonModules/%D1%8F%D1%8F_%D0%A3%D1%81%D0%BB%D0%BE%D0%B2%D0%B8%D1%8F%D0%9E%D0%BF%D0%BB%D0%B0%D1%82%D1%8B%D0%9F%D1%80%D0%BE%D0%B4%D0%B0%D0%B6%D0%B8/Ext/Module.bsl#L1
```

Якорь `#L1` **не спасает**, если путь уже percent-encoded. Исправить encoding в рендерере
нельзя — агент обязан отдавать UTF-8 в `[]()`.

Рабочие варианты для того же файла (строка 1):

```markdown
[Module.bsl:1](conf/CommonModules/яя_УсловияОплатыПродажи/Ext/Module.bsl#L1)
```

Указать строку **без показа кода** — только markdown `#L` (см. §3). Code citation без тела
**не рендерится** в Cursor (пустой блок).

Показать саму строку 1 — citation **с текстом кода** внутри:

````markdown
```1:1:conf/CommonModules/яя_УсловияОплатыПродажи/Ext/Module.bsl
////////////////////////////////////////////////////////////////////////////////
```
````

## Рабочие форматы

### 1. Code citation — показать фрагмент кода в ответе

Ограждение на **отдельной строке**, без префикса списка. Путь — UTF-8 от корня репозитория.
**Тело блока обязательно** — хотя бы одна строка исходного кода. Пустой citation в Cursor
**невидим** (пустой прямоугольник без текста и без кликабельного заголовка).

**Не использовать** citation как «ссылку на строку без кода» — для этого `[label](path#Ln)`.

````markdown
```42:50:conf/CommonModules/яя_УсловияОплатыПродажи/Ext/Module.bsl
Функция Пример() Экспорт
    // ...
КонецФункции
```
````

| Когда | Формат |
| --- | --- |
| Показать код из файла | `startLine:endLine:относительный/путь` |
| Одна строка | `42:42:conf/.../Module.bsl` |
| `.bsl`, `.xml`, любой текстовый файл | тот же синтаксис |

Клик по заголовку блока открывает файл на указанных строках.

### 2. Markdown-ссылка — файл без тела кода

```markdown
[Module.bsl](conf/CommonModules/яя_УсловияОплатыПродажи/Ext/Module.bsl)
```

Короткая подпись в тексте: [design.md](../openspec/changes/example/design.md) — путь
относительно текущего артефакта в `openspec/`, если так принято в папке change.

### 3. Markdown-ссылка — файл и строка (без тела кода)

Предпочтительный способ **указать место**, не цитируя код:

```markdown
[Module.bsl:1220](conf/CommonModules/яя_УсловияОплатыПродажи/Ext/Module.bsl#L1220)
[Module.bsl:42–50](conf/CommonModules/яя_УсловияОплатыПродажи/Ext/Module.bsl#L42-L50)
```

Якорь `#L…` — только в **markdown-ссылке**, не в code citation (там диапазон в заголовке блока).

### 4. Выбор формата

| Задача | Формат |
| --- | --- |
| Указать файл/строку без кода | `[label](path#Ln)` — **первый выбор** |
| Показать кусок кода в ответе | code citation с **непустым** телом |
| Ссылка в `docs/` / OpenSpec / handoff | `[label](path)` |
| Несколько файлов в списке | каждый — отдельная markdown-ссылка |

## Обязательные правила пути

- От **корня репозитория**: `conf/…`, `docs/…`, `openspec/…` — не `/work/conf/…`, не `c:\…`.
- Разделитель **`/`** (даже если агент в Linux agent-slot).
- Кириллица и пробелы — **как на диске**, без `encodeURI` / `%D0%…`.
- В agent-slot workspace = `/work`, но в ссылках всё равно `conf/…` — Cursor на хосте
  резолвит от корня открытого worktree.

## Не работает — не использовать

| Антипаттерн | Почему |
| --- | --- |
| Percent-encoding в пути | `%D1%8F%D1%8F_…` — не открывается в Cursor |
| Encoded путь + `#Ln` | `…%D0%…/Module.bsl#L1` — якорь не помогает |
| Голый `path` или `path#Ln` без `[]()` | рендерер auto-encode-ит кириллицу → см. строку выше |
| `` `conf/…/файл.bsl` `` в чате | информативно, **не** file-link по клику |
| `file:///C:/…` / `file:///work/…` | не резолвится как файл проекта |
| Wikilinks `[[conf/…]]` | Obsidian, не Cursor |
| Абсолютный Windows-путь | `C:\path\to\…` — только если нет относительного |
| Code citation **без тела** | пустой блок — невидим в Cursor; для строки без кода — `[](path#Ln)` |
| Code citation с `#L42` в заголовке | якорь только в markdown `[](path#L42)` |
| Code citation с префиксом списка | `- ```12:34:path` ломает разбор |

## Agent-slot и хост

Поведение **одинаковое**: UTF-8 markdown или code citation от корня git.
Различие только в cwd агента (`/work` в слоте) — на формат ссылок не влияет.

Проверка перед отправкой ответа:

1. В URL видна кириллица (не `%D0%…`).
2. Путь оформлен как `[текст](path)`, `[текст](path#Ln)` или code citation.
3. Только строка/место без кода → `[label](utf8path#Ln)`; citation — только с телом кода.

## Связанные правила

- Имена **новых** файлов агентом — латиница ([markdown-formatting.md § Имена](markdown-formatting.md));
  существующие кириллические пути в `conf/` и legacy `docs/` не трогать.
- Handoff, OpenSpec, review: те же форматы ([handoff/SKILL.md](../../.cursor/skills/handoff/SKILL.md)).
- Реестр cursor rules: [cursor-rules.md](cursor-rules.md).
