# Интегратор: роль, цикл, шаблоны

Процесс «дочки-интегратора» — вторая половина конвейера агентов; первая —
[agent-orchestration.md](agent-orchestration.md) (оркестратор: спавн, брифы,
приёмка, архивация). Границы: **кит** описывает роль, цикл, шаблоны и стыки;
**проект** — окружение и его грабли (`dev-ib-ibsrv.md`, `load-config-to-dev.md`,
`mcp-server*.md`).

## Зачем отдельный тред

Загрузка в общую ИБ — единственная операция, меняющая состояние, видное всем.
Пока её делает каждый исполнитель сам, получаем: параллельные `apply`, драки за
монопольный режим, чужие грязные файлы в чек-ауте, разъехавшийся EOL и «зелёные»
логи без изменений в базе. Поэтому: **один загрузчик — тред-интегратор**;
оркестратор сам не мержит и не грузит.

## Роль и границы

Интегратор — не «мальчик с кнопкой». Он отвечает за:

- **приёмку дельты**: что вливается, нет ли чужих файлов, сохранён ли EOL, не
  тронуты ли `Configuration.xml`, `ConfigDumpInfo.xml` и gitlink кита;
- **выбор пути загрузки**: динамическое обновление или оффлайн-цикл (метаданные);
- **доказательства применения** (см. ниже), а не «лог зелёный»;
- **живую проверку** и тесты;
- **отчёт** по фиксированному формату.

Не входит: писать код конфигурации, чинить найденные дефекты (возвращает тому,
кто исполнял), решать, что считать приёмкой, писать в прод.

**Один интегратор на ИБ.** Единообразие работы и знание окружения — его главная
ценность, поэтому тред долгоживущий, а не «на одну загрузку». Если несколько
оркестраторов работают с одной ИБ, интегратор всё равно один: правило
«одна ИБ — один загрузчик» сильнее удобства отдельных тредов. Разные ИБ —
разные интеграторы.

## Цикл (6 шагов, с точками остановки)

1. **Приём задания.** Из брифа понятно: ветка + sha, что внутри, метаданные или
   нет, какие проверки. Нет — стоп, вопрос оркестратору.
2. **Проверка дельты (read-only).** Список файлов; EOL **по блобам**, а не по
   рабочим файлам; нет `Configuration.xml`, `ConfigDumpInfo.xml`, изменений
   gitlink кита; нет чужой грязи, которая уедет в мерж.
3. **Мерж в основную ветку.** Конфликты — по смыслу, с объединением разделов, а
   не «взять одну сторону». После мержа — проверка EOL по staged-блобам: ручная
   правка в конфликте сбрасывает CRLF/LF молча.
4. **Загрузка.** Метаданные менялись (XML объектов, формы, роли, расширения) →
   **оффлайн-цикл**: стоп узла → импорт → `apply --force` → старт. Только модули →
   динамическое обновление, узел **не** останавливается. Перед оффлайн-циклом —
   предупредить оркестратора: остановка рвёт сессии работающих в базе.
5. **Доказательства применения — три, все обязательны.** `conf: N файлов` +
   смена поколения конфигурации + «Обновление конфигурации базы данных успешно
   завершено». «УСПЕХ» без смены поколения = импорт пропущен (кэш загрузчика).
6. **Живые проверки, тесты, отчёт.** Открыть проверяемое, прогнать суиты,
   сверить с baseline, назвать новые красные, закрыть UI-сессию (`clean_data`).
   После отчёта освободить чек-аут: никаких staged-файлов и незавершённых мержей.

## Матрица «симптом → реакция»

| Симптом | Что на самом деле | Реакция |
| --- | --- | --- |
| «УСПЕХ», в логе `conf: 0 файлов` | кэш срезал файл | `SKIP_CONFIGURATION_CACHE=true` + список |
| Промпт «Повторить / Обновить» | база занята | ответ `3` или освободить базу |
| «Уже работает конфигуратор» | чужой/зависший запуск | перезапуск узла |
| Узел жив, MCP жив, форма мертва | мёртв веб-клиент | проверить код `:8315`, перезапуск |
| Узел умер сразу после `apply` | известное поведение | перезапуск, одна попытка |
| `--list-file` не найден | MSYS переписал путь | Windows-путь или `MSYS_NO_PATHCONV=1` |
| Тишина в чате, команда не вернулась | heredoc ждёт stdin | снять процесс, heredoc не использовать |
| «Находок нет» на сломанном файле | чек не выполнялся | проверить, не «пропущен» ли чек |
| Объект «применён», но его нет | импорт не сохранился | проверка живьём по метаданным |

## Стыки

- **Оркестратор → интегратор**: бриф (шаблон ниже). Оркестратор не грузит сам.
- **Исполнитель → интегратор**: ветка и sha; исполнитель **не** грузит. Спорные
  находки возвращаются исполнителю, а не правятся интегратором.
- **Ревьюер → интегратор**: пока не вынесен вердикт содержательного ревью,
  загрузка не начинается. Проверено на живой ошибке: загрузка успела примениться
  за минуты до СТОПа, и в базе оказалась версия, которую ревью признал вредной.
- **Интегратор → оркестратор**: отчёт, стоп-сигналы (красные тесты, расхождение
  EOL, чужая блокировка) и вопросы — сразу, не «догадаюсь сам».

## Контекст и ротация

Работа интегратора единообразна: ценны окружение и текущая задача, детали прошлых
загрузок — балласт. Поэтому:

- **долговечное знание живёт в документах, а не в контексте** (эти правила,
  `memory/`, проектные грабли) — тогда сжатие ничего не стоит;
- **сжимать между циклами**, когда тред простаивает и чек-аут чист. Сжатие
  **посреди цикла опасно**: узел может быть остановлен, файлы staged, мерж
  незавершён — состояние потеряется;
- **ротация вместо сжатия**: если тред деградировал или контекст перевалил за
  ~65–70 %, спавним свежего интегратора, а не выжимаем старый.

## Техника и обходы

- **Коммиты в кит из ворктри дочек забираются до всего остального:** у ворктри
  свой git-dir сабмодуля, он уедет вместе с ворктри при архивации:
  `git -C harness fetch <ворктри-дочки>/harness <ветка>:refs/heads/<ветка>`.
- **Загрузка — под таймаутом и с ретраями** (до 3 попыток). Признак залипания:
  счётчики I/O не растут при CPU ~100 %, файл ИБ не меняется — снимать, не ждать.
- **Файл, на котором спиннит загрузка** (обычно тянущий `Configuration.xml`):
  двухшаговый обход — полная загрузка без него, затем частичная с ним и
  `SKIP_CONFIGURATION_CACHE=true`.

## Шаблон брифа оркестратора

```text
Задание N: <что вливаем> (`<sha>`, ветка `<branch>`).
Что внутри: <файлы и суть>, метаданные: да/нет.
Проверки: EOL по блобам; <тесты и ожидания>; <живые проверки>.
Ограничения: узел останавливать <да/нет>; чужие файлы не трогать.
Отчёт: мерж-sha, поколение, файлов/время, живые проверки, тесты, узел.
```

## Шаблон отчёта

```text
Задание N (<sha>) — <статус одной строкой>.
Мерж: <sha>. EOL/BOM: <по блобам>. Поколение: <хеш>.
Загрузка: <путь>, <файлов>, <время>, <успех/ошибки>.
Живые проверки: <что смотрел и что увидел>.
Тесты: <суита1>, <суита2>; новые красные: <нет/список>.
Состояние узла: <pid, порт, web-код>.
Не проверено: <что и почему>.
```
