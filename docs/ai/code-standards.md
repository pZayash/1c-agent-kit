# Стандарты кодирования и форматирования

Единый прогон проверок (BSL, spec-lint, XML, markdown) — скрипты потребителя
(`check-changed.sh` / `tools/check-all/`), **если есть**.

## Код модулей

### Модуль менеджера (`ManagerModule.bsl`)

Все объявления `Процедура` / `Функция` MUST быть внутри препроцессорного
`#Если … Тогда` … `#КонецЕсли`, где множество условий **содержит**
`Сервер`, `ТолстыйКлиентОбычноеПриложение`, `ВнешнееСоединение`
(порядок операндов, регистр `Или`/`ИЛИ`, пробелы не важны; лишние условия
допустимы). Иначе толстый клиент управляемого приложения компилирует методы
на клиенте и падает на серверных типах/вызовах.

Чек (если есть у потребителя): `manager-module-wrap-lint`.

### Обязательные правила

- Всегда писать комментарии к модулям и методам (ИИ-агентам ко всем методам, людям к экспортным методам)
- Улучшать где возможно стилистику модуля и кода, без дополнительных заданий
- При обработке ошибок в `Попытка ... Исключение ... КонецПопытки` всегда писать
  в журнал регистрации при исключении (обёртка журнала потребителя, если есть;
  иначе `ЗаписьЖурналаРегистрации`)
- Код в области правок потребителя должен проходить проверку BSLLS или иметь
  комментарий о существенной причине отступления
- Новые методы должны располагаться в соответствующих областях (`#Область`) по правилам проекта
- Сортировка методов внутри областей: сначала по логической связанности, затем по алфавиту
- В названиях методов избегать латиницы, использовать только русский язык

### `ПередЗаписью`: не менять данные документа

В `ПередЗаписью` документа **нельзя** «тихо» править содержимое за пользователя.
Запись — решение пользователя; содержание документа — его ответственность.

Допустимо:

- предупредить (`СообщитьПользователю`);
- запретить проведение / запись (`Отказ`);
- валидировать и показать расхождение.

Недопустимо: автозамена реквизитов/строк ТЧ «чтобы стало правильно» в
`ПередЗаписью` (и аналогичных точках, где пользователь уже подтвердил запись).

### Ограничения использования методов

- Не использовать метод `НСтр()`. В конфигурации используется только один язык — русский; `НСтр()` усложняет код без пользы
  - Правильно: `Заголовок = "Калькуляция"`
  - Неправильно: `Заголовок = НСтр("ru = 'Калькуляция'")`
- Не использовать `ОбщегоНазначения.ПодставитьПараметрыВСтроку`, использовать `СтрШаблон()`
- Не использовать инициализацию параметров методов вложенными методами формирования строк

### Изменение кода типовых модулей

- Изменения в типовом коде должны быть минимальны для облегчения обновления
- Желательно ограничиваться "Инъекциями" в типовой код (однострочными вызовами методов или корректировками переменных)
- Новые методы помещать в область правок потребителя в **конце** модуля
- Не оставлять в модуле закомментированный типовой код, удалять
- **Логику не вшивать в тело типового метода даже ради локальной переменной.**
  Соблазн «нужные данные (`МассивЗаказов`, локал) тут под рукой» — не повод писать
  цикл/ветвление в типовом коде. Если есть свой обработчик/подписка, получающий
  те же данные через параметр (`ДанныеЗаполнения.*`) — логика туда; в типовом
  методе максимум однострочный вызов. Многострочная вставка в типовой = находка ревью.

Маркер комментария правок типового (формат, обязательность, vendor-merge) —
в доке потребителя, если есть.

## Обязательные правила форматирования кода

- `#КонецОбласти`, `#КонецЕсли`, `КонецПроцедуры`, `КонецФункции` (уровень модуля)
  закрывать с семантическим комментарием: `// </Имя…>` (формат: угловые скобки в комментарии;
  на внутренние `КонецЕсли` / `КонецЦикла` не распространяется)
- Не вкладывать `#Область ДляВызоваИзДругихПодсистем` внутрь `ПрограммныйИнтерфейс` —
  дублирование; достаточно одной области и комментария подсистемы БСП
- Отступы табами
- Не выравнивать табуляциями и пробелами слова в коде по символам `=`, `,` и подобным
- Не использовать два пробела подряд
- Обязательно отделять логические и математические операторы пробелами с двух сторон
- Избегать использования латинских и кириллических символов вместе в именах переменных (кроме общепринятых аббревиатур: JSON, HTTP, XML)

## Рекомендованные правила форматирования кода

- Пустая строка после `Если ... Тогда` перед `КонецЕсли`
- Комментарии к параметрам `СтрШаблон`: `// %1`, `// %2`, кроме последнего параметра
- Имена процедур и функций в PascalCase
- Имена реквизитов форм, переменные внешнего контекста метода в PascalCase
- Локальные переменные методов в loweCamelCase на русском языке
- Допустимо комбинировать snake_case для обозначения виртуальной иерархии методов

## Запросы

- Тексты запросов выравнивать по началу строки
- Параметры запроса присваивать перед определением текста запроса
- Всегда использовать "ВЫБРАТЬ РАЗРЕШЕННЫЕ ..." в тексте запроса
- Не использовать вложенные запросы, кроме крайне простых
- Запрещено обращаться к пакету результатов запроса по индексу

Hard rules запросов — скилл `1c-query-rule` в `.cursor/skills/` потребителя,
если есть. Обзор: [query-standards.md](query-standards.md).

### Пример типового оформления

```1c
запрос = Новый Запрос;
запрос.УстановитьПараметр("Параметр1", ЗначениеПараметра1());
запрос.Текст =
"ВЫБРАТЬ РАЗРЕШЕННЫЕ
|Т.Ссылка КАК Ссылка,
|ИЗ ... ";
```

## Чек-лист ревью производительности

Проверяй эти анти-паттерны после правок BSL-кода:

- **Запрос в цикле**: вместо `Новый Запрос` внутри `Для Каждого` собери
  список ключей и выполни один пакетный запрос.
- **Прямой доступ к реквизитам ссылок**: в циклах и массовой обработке не
  используй `Контрагент.ИНН`. Читай реквизиты через
  `ОбщегоНазначения.ЗначенияРеквизитовОбъекта` или пакетный запрос.
- **Вложенный запрос в списке выбора**: вместо подзапроса в поле `ВЫБРАТЬ`
  используй соединение с агрегированной временной таблицей.
- **Фильтр виртуальной таблицы в `ГДЕ`**: условия по измерениям регистров
  передавай в параметры виртуальной таблицы.
- **Нет ограничения выборки**: если нужен небольшой набор строк, используй
  `ПЕРВЫЕ N`.
- **Много клиент-серверных вызовов подряд**: объединяй данные в один серверный
  вызов и возвращай структуру результата.
- **`&НаСервере` без доступа к форме**: если метод не читает реквизиты формы,
  используй `&НаСервереБезКонтекста` и передавай значения параметрами.
- **Повтор дорогого расчета**: кэшируй результат в `Соответствие` в пределах
  вызова или выноси в регистр сведений, если кэш нужен между сеансами.
- **Вложенные циклы поиска**: замени `O(n^2)` на индекс по `Соответствие` или
  индексы таблицы значений.
- **Глубокая вложенность**: используй ранний выход после проверок предусловий.

## Чек-лист корректности

Проверяй после правок BSL-кода:

- **Мёртвый параметр-флаг**: добавил параметр, меняющий поведение
  (`пТолькоПустые`, режим, флаг) — убедись, что он **читается в теле** метода.
  BSL не предупреждает о неиспользуемом параметре. Проверка: поиск имени
  параметра внутри процедуры; одно вхождение (только сигнатура) — баг.
- **Скрытые побочные эффекты**: метод делает ровно то, что заявлено в его
  комментарии-контракте. Не дописывай запись чужих реквизитов или состояния
  «заодно» — это ломает ожидания вызывающего. Новое поведение → отдельный метод,
  а не побочный эффект.

## Константы и литералы

- Литералы, используемые в нескольких местах, — в функции модуля литералов потребителя
- Ссылки на именованные объекты, предопределенные значения, "волшебные числа" —
  в функции модуля констант потребителя

## Сообщения пользователю в UI

### Клиент, открытая форма

Неблокирующее сообщение **у поля реквизита** (не только в панели внизу) — через
`ОбщегоНазначенияКлиент.СообщитьПользователю` с заполненным параметром `Поле`:

```1c
// Текст — у поля Контрагент на форме документа
ОбщегоНазначенияКлиент.СообщитьПользователю(
    Текст,
    пФорма.Объект.Ссылка,
    "Объект.Контрагент");
```

Сигнатура: `СообщитьПользователю(Текст, КлючДанных, Поле, ПутьКДанным, Отказ)`.

| Параметр | Назначение |
| --- | --- |
| `КлючДанных` | Ссылка на объект формы (`пФорма.Объект.Ссылка`); для нового документа — пустая ссылка |
| `Поле` | Путь к реквизиту относительно данных формы: `"Объект.Контрагент"` и т.п. |
| `Отказ` | По умолчанию `Ложь` (advisory); `Истина` — блокирующая проверка |

Вызов **без** `Поле` — только панель сообщений внизу, поле не подсвечивается.

### Сервер, проверка при записи

Блокирующие сообщения — `ОбщегоНазначения.СообщитьПользователю` (или
`ОбщегоНазначенияКлиентСервер.СообщитьПользователю`) с `Отказ = Истина`:

```1c
ОбщегоНазначения.СообщитьПользователю(ТекстСообщения, , "Объект.Контрагент", , Отказ);
```

### Текст сообщения

- Формировать через `СтрШаблон`; литеральный `%` в конце — `%%` (иначе ошибка шаблона).
- Не использовать `НСтр()` (см. выше).

## Логирование

- Писать в журнал через обёртку потребителя, если есть; иначе
  `ЗаписьЖурналаРегистрации`
- Все ошибки в `Попытка/Исключение` логировать

Стратегия (уровни, нейминг) — дока потребителя, если есть.
