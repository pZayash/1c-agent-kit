# Формат рабочей памяти

Папка `memory/` у потребителя — рабочие факты в markdown. Не путать с
`docs/ai/` (стабильные инструкции) и `memory.md` (только глобальные правила).

## Принципы

- Одна запись = один `.md`-файл. Один факт = одна запись.
- Коротко и предметно. Файл самодостаточен.
- Не хранить секреты, токены, пароли, персональные данные сверх необходимости
  аналитики (тогда — минимум, без контактов).

## Именование

`YYYY-MM-DD-short-topic.md` — дата и slug **латиницей**.

Пример: `2026-04-27-qmd-path-filter.md`.

## Шаблон записи

```md
# <Короткий заголовок факта>

## Контекст
<Где проявляется: объект, модуль, подсистема>

## Факт
<Что выяснили или о чем договорились>

## Решение / правило
<Как действовать в будущих задачах>

## Теги
<2-6 тегов; канон — TAGS.md в корне потребителя>

## Дата и источник
<YYYY-MM-DD, кто зафиксировал, ссылка на задачу/чат при наличии>
```

Словарь домена — `CONTEXT.md`. Теги — `TAGS.md` (лениво, при первом теге).

## Разлад (поведение агента)

Staging: `memory/rule-friction/` (папка ленивая). Один файл = один сигнал.
Всё в папке = pending. Скилл `evolve` у потребителя (overlay kit).

Не путать с «Запомни» (факт домена в `memory/*.md`).

## Уроки сессии

Агент сам наступил и победил (XML дампа, UI-тест) — сразу запись сюда.
Перенос в `docs/ai/` — только с согласия оператора:
[agent-session-lessons.md](agent-session-lessons.md).

## Поиск

Если у потребителя есть `qmd`:

```bash
qmd query "…" --path "memory/"
qmd search "FAQ" --path "memory/"
```

Иначе — узкий поиск по `memory/`. Перед нетривиальной задачей:
`memory.md` → `memory/` → при необходимости `CONTEXT.md`.

Раскладка папок: [docs-layout.md](docs-layout.md).
