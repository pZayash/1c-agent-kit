# Правила написания запросов

Точка входа по запросам. Сначала этот файл, потом только нужные компаньоны —
не грузить весь набор «на всякий случай».

> **Граница.** Hard rules (формат, псевдонимы, ВТ, запреты) — в скилле
> `1c-query-rule` (`.cursor/skills/` потребителя). Здесь — маршрутизация,
> pre-flight и **проектные** доп.требования.

## Маршрутизация

| Задача | Открыть |
| --- | --- |
| Hard rules (формат, `КАК`, параметры, нет запросов в циклах, фильтр ВТ через параметры) | скилл `1c-query-rule` в `.cursor/skills/` потребителя |
| Доп.требования проекта (имена периода, пакет→ВТ, динамический текст) | § [Дополнительные требования](#дополнительные-требования) ниже |
| Запрос внутри СКД / отчёта | [скд.md](скд.md) + скилл `1c-query-rule` |
| Запрос по проектируемому / перестраиваемому регистру | сначала [регистры.md](регистры.md), потом этот роутер |
| Блокировки вокруг «запрос + запись» | [locks-and-transactions.md](locks-and-transactions.md) |
| Антипаттерны запросов (цикл, ВТ в `ГДЕ`, нет `ПЕРВЫЕ N`) | `anti-patterns.md` (в планах) + скилл `1c-query-rule` |

## Pre-flight (каждый нетривиальный запрос)

1. **Проверить метаданные** до первого `ВЫБРАТЬ` — MCP `metadata_get` /
   `get_metadata_structure` / `object_get`, либо XML в `conf/`. Не выдумывать
   имена реквизитов и табличных частей.
2. **Найти эталонный скелет** — `qmd query` / `qmd search` / узкий `rg` по
   похожим запросам в `conf/` до изобретения нового каркаса.
3. **Выбрать правильный источник** — справочник / документ / срез регистра
   сведений / виртуальная таблица накопления (`Остатки`, `Обороты`,
   `ОстаткиИОбороты`). Неверный источник — дефект дизайна, не проблема тюнинга.
4. **Hard bans** из скилла `1c-query-rule` — нет запросов в циклах, всегда
   параметры, всегда `КАК`, фильтр виртуальных таблиц через параметры (не
   `ГДЕ`), промежуточная переменная для `Запрос.Выполнить()`.

## Порядок загрузки

```text
query-standards.md (этот файл)
  → скилл 1c-query-rule          # hard rules
  → скд.md / регистры.md         # только если задача про СКД или регистр
  → locks-and-transactions.md    # только если вокруг запись
```

## Дополнительные требования

- Период в параметрах запроса: канон **`&ДатаНачала`** / **`&ДатаОкончания`**
  (допустимо `&Начало` / `&Окончание`; не `&Конец` — легко перепутать границы)
- Тексты запросов должны открываться стандартным конструктором запросов
- Помещай результат запроса во временную таблицу и выбирай все из этой временной
  таблицы в месте использования (запрещено обращаться к пакету результатов по
  индексу)

### Динамический текст запроса

В динамически собираемом тексте запроса **не использовать** `%1`/`%2` через
`СтрШаблон` — конструктор и BSLLS не парсят такой текст.

Вместо этого:

- подставлять **действительное имя таблицы** в шаблоне и менять через `СтрЗаменить`;
- либо псевдопараметр `&МестоВставки` и `СтрЗаменить` перед `УстановитьПараметр`.

`СтрШаблон` — для сообщений и логов, не для текста запроса.

```bsl
// Плохо
Запрос.Текст = СтрШаблон("ВЫБРАТЬ ... ИЗ %1.КонтактнаяИнформация КАК КИ", ИмяТипа);

// Хорошо
ШаблонЗапроса =
"ВЫБРАТЬ КИ.Ссылка
|ИЗ Справочник.Контрагенты.КонтактнаяИнформация КАК КИ";
Запрос.Текст = СтрЗаменить(ШаблонЗапроса,
    "Справочник.Контрагенты.КонтактнаяИнформация",
    ИмяТипа + ".КонтактнаяИнформация");
```
