# Уроки сессии агента: memory → docs

Цикл, когда агент **сам** столкнулся с проблемой, разобрался и решил
(не просто прочитал готовую доку).

Канон для [`/close-chat`](../../cursor/skills/close-chat/SKILL.md) — шаг **0б**.

## Области (обязательно, если применимо)

| Область | Примеры | Куда в `docs/ai/` (kit или addendum) |
| --- | --- | --- |
| XML метаданные дампа | XDTO при load, `meta-edit`, `Form.xml`, ТЧ, квалификаторы | [metadata-xml-load-pitfalls.md](metadata-xml-load-pitfalls.md), [object-conventions.md](object-conventions.md), [load-config-to-dev.md](load-config-to-dev.md) |
| WEB-тест UI | селекторы, логин, headless, гибрид с MCP | skill `web-test`; плейбук потребителя, если есть |

Другие домены — тот же принцип, если урок повторяемый.

Путь дампа: `src/cf` (Vanessa) или `conf/` (legacy) — как у потребителя.

## Во время сессии

Сразу после решения — запись в `memory/` ([memory-format.md](memory-format.md)):

1. **Контекст** — объект, скилл, команда, симптом.
2. **Факт** — в чём ловушка.
3. **Решение / правило** — как не наступить снова.
4. **Теги** — по `TAGS.md` потребителя.

Не откладывать на `/close-chat`. Если правило уже в `docs/ai/` — в memory
ссылка + нюанс сессии.

## Перед `/close-chat`

Агент **не** переносит memory → docs сам (оператор решает объём).

Шаг **0б**: один вопрос, если были новые/обновлённые записи `memory/` по таблице:

> «В сессии зафиксированы уроки: … Перенести в `docs/ai/` (какие файлы)?»

Ответ: да (файлы) / отложить / нет.

Уроков не было — одна строка «уроков для переноса в docs нет».

## Что переносить

- Повторяемое правило, чеклист, антипаттерн.
- Ссылка на skill/скрипт.
- Не дублировать `implementation-notes.md` OpenSpec.

Стабильное глобальное правило после нескольких подтверждений — в `memory.md`.

Раскладка: [docs-layout.md](docs-layout.md).
