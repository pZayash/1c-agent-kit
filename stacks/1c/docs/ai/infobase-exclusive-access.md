# Монопольный доступ к базе: кто держит и как освободить

Операции уровня конфигурации — выгрузка базы (`ibcmd infobase dump`), сохранение
CF (`ibcmd infobase config save`, `1cv8 DESIGNER /DumpCfg`), загрузка/применение
(`config load` / `config apply`, `/LoadConfigFromFiles`, `/UpdateDBCfg`) — требуют
**монопольного доступа**. Базу при этом может держать не только «сеанс
пользователя»: чаще всего её держат фоновые процессы — веб-публикация,
автономный сервер, зависший конфигуратор или клиент тестирования.

> **Граница.** Здесь — блокировки **уровня базы** (кто занял ИБ как файл/сервер).
> Транзакционные блокировки и дедлоки данных — в
> [locks-and-transactions.md](locks-and-transactions.md).

## 1. Симптомы

| Сообщение (в логе может быть CP866) | Что значит |
| --- | --- |
| «Ошибка исключительной блокировки информационной базы» | Кто-то держит ИБ; операция не началась |
| «Не удалось заблокировать информационную базу для конфигурирования» | То же, конфигураторный путь |
| «Ошибка блокировки ИБ» при `/UpdateDBCfg` / `/LoadConfigFromFiles` | То же, загрузка конфигурации |
| «Файл уже используется другим приложением» (файловая ИБ) | Внешний процесс держит `1Cv8.1CD` / файлы сеансов |

Симптом всегда один и тот же по сути: **процессов `1cv8*` не видно, а база
занята**. Отсутствие клиентов в диспетчере задач ничего не доказывает.

## 2. Кто держит базу

| Источник | Признак | Как освободить |
| --- | --- | --- |
| **Apache + веб-модуль 1С** | служба `Apache2.4` / `apache2`, процессы `httpd` | остановить службу |
| **IIS + веб-модуль 1С** | пул приложения, `w3wp.exe`, `wsisapi.dll` | `iisreset /stop` или стоп пула |
| **Автономный сервер `ibsrv`** | процесс `ibsrv` (узел с базой) | остановить узел (skill `db-server`) |
| **Конфигуратор** | `1cv8.exe` c `/DumpCfg`, `/UpdateDBCfg`, `/LoadConfigFromFiles` | `taskkill /F /IM 1cv8.exe` |
| **Клиентские сессии** | `1cv8c.exe` / `1cv8.exe`, клиент тестирования, Answer42 | закрыть клиент / `stop_session` |
| **Кластер 1С** (серверная ИБ) | `rmngr`/`rphost`, сеансы в кластере | закрыть сеансы (консоль / `rac`) |
| **Забытый пакетный процесс** | `ibcmd.exe`, `1cv8.exe` в фоне после обрыва | `taskkill /F /IM ibcmd.exe` |
| **Антивирус/индексатор** (файловая ИБ) | блокировка `1Cv8.1CD` извне | исключение каталога базы |

Команды освобождения (пример для Apache, Windows):

```bash
powershell -NoProfile -Command "Stop-Service -Name 'Apache2.4' -Force"
# Linux: apachectl stop
# IIS:   iisreset /stop   (или appcmd stop apppool /apppool.name:"<пул>")
# клиент тестирования / автотесты: stop_session {"clean_data": true}
```

Правило: **любой источник, который «смотрит» в базу — держит её**. Публикация
веб-доступа держит базу постоянно, даже когда никто не работает в браузере:
веб-модуль открывает соединение и не отпускает его между запросами.

## 3. Диагностика (порядок)

```bash
# 1) процессы 1С и веб-серверов
tasklist | grep -Ei "1cv8|ibcmd|ibsrv|httpd|w3wp"

# 2) публикация жива? (если да — почти наверняка веб-модуль и держит)
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1/<публикация>/

# 3) файловая ИБ: файлы сеансов/блокировок рядом с 1Cv8.1CD
ls -la "<каталог ИБ>" | grep -Ei "1Cv8.1CL|\.cfl"
```

Для серверных баз дополнительно — сеансы кластера (консоль администрирования или
`rac`); для автономного сервера — статус узла (`ibcmd infobase ... --pid=<pid>`,
команды skill `db-server`).

## 4. Рецепт: остановить → сделать → поднять → проверить

```bash
# 1. остановить держателя (пример: Apache)
powershell -NoProfile -Command "Stop-Service -Name 'Apache2.4' -Force"

# 2. операция с монопольным доступом (пример: выгрузка CF, пакетный режим ibcmd)
ibcmd infobase config save --db-path="<каталог ИБ>" \
  --user="<user>" --password="<pw>" "<out.cf>" < /dev/null

# 3. поднять держателя
powershell -NoProfile -Command "Start-Service -Name 'Apache2.4'"

# 4. проверить, что вернулось
powershell -NoProfile -Command "(Get-Service Apache2.4).Status"      # → Running
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1/<публикация>/  # → 200/301
```

Проверка после подъёма — **обязательна**: оператор может заметить «сайт не
работает» гораздо позже, чем вы закончите. Если публикация обслуживает MCP-канал,
дополнительно проверьте его (`tools/mcp-call` / `version_get`).

## 5. Ловушки

- **`config save` / `infobase dump` — это чтение, но монопольное.** Файловая база
  не даёт исключительный доступ, пока её держит веб-модуль. Останавливать
  веб-сервер на время выгрузки — норма, а не костыль.
- **`ibsrv` и веб-публикация могут смотреть в разные базы.** Остановка одного
  узла не освобождает другую базу; проверяйте, на какую базу смотрит каждый.
- **Прерванный запуск конфигуратора оставляет сеанс.** После `Ctrl+C`, таймаута
  агента или падения процесса база остаётся занятой; проверяйте `tasklist` перед
  повтором, а не после третьей неудачной попытки.
- **Не убивайте процесс, который нужен человеку.** `taskkill /IM 1cv8.exe`
  убьёт и открытый конфигуратор с несохранёнными правками; сначала уточните, что
  запусков несколько.
- **Загрузка (`config load`/`apply`, `/LoadConfigFromFiles`) требует монополии
  строже, чем выгрузка.** На файловой базе — оффлайн (`--db-path`), на
  серверной — через узел автономного сервера/кластер.
- **Windows-служба может требовать прав администратора.** Остановка через
  `Stop-Service` из обычного шелла работает, если служба установлена этим же
  пользователем; иначе — запуск с повышением.
