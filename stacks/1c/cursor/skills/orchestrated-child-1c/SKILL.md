# orchestrated-child-1c — 1C-дополнение к orchestrated-child

Читается из `orchestrated-child` до шага 1,
когда у потребителя выбран стек `1c`. Конкретизирует стоп-зону и бутстрап
под 1С; порядок остальной — по core-версии.

## Стоп-зона — 1С-механика

- «Общий целевой runtime» из core-версии — это **общая ИБ**. «Загрузка» —
  загрузка конфигурации из `conf/` (`/UpdateDBCfg` и полная загрузка
  включительно — запрещены без явной команды). Мерж и загрузку делает
  дочка-интегратор ([integrator](../integrator/SKILL.md)).
- Почему жёстко: ИБ одна, загрузка из твоего ворктри делает её конфигурацию
  равной **твоему** дампу — чужие незакоммиченные объекты при этом исчезают
  из метаданных, а кэш загрузки в ворктри «не знает», что реально лежит в базе.

## Бутстрап — 1С-специфика

Отсутствие в свежем worktree — норма:

- кэш дампа `conf/ConfigDumpInfo.xml` — gitignored;
- `tools/bsl-check/` (BSL-сервер) и `tools/mcp-call/` — бинари не из git;
- дампы типовой конфигурации;
- `.env` — адрес ИБ, креды, режимы; нужен, если запускаешь что-то с базой;
- `.mcp.json` — без него `dev_dt`/`prod_dt` и MCP-поиск «недоступны». Это не
  сбой базы и не ночная перезаливка, а отсутствие конфига.

## Проверки — 1С-стек

После каждого блока правок: XML well-formedness
([xml-wellformed](../xml-wellformed/SKILL.md)), `check-bsl.py`
([bsl-check](../bsl-check/SKILL.md)), общий чек на изменённых файлах
(`check-changed.sh`).

Долгоживущий фоновый процесс в наблюдениях core-версии — загрузка
конфигурации может идти часами без событий.
